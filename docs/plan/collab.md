# Модуль collab (CL)

## 1. Цель
Фаза 2 (`docs/roadmap.md` §10): чат и документы. Оба — модули `modules/chat` и `modules/docs` по C-modules (включаются и выключаются), на той же синхронизации, что и задачи.

## 2. Решения пользователя
- Фаза 2: чат, документы, учёт времени и спринты, автоматизации и webhooks (2026-10-23). Учёт времени, спринты, автоматизации и webhooks — модуль `work`.
- Простота, быстрый интерфейс, бюджеты `docs/roadmap.md` §7 не ухудшаются; начальный JS ≤ 200 КБ, модули — ленивыми чанками.
- В `main` — только с одобрения пользователя.

## 3. Контракты
- **Потребляем:** `docs/contracts/core.md`, `core-mutators.md`, `core-api-v1.md`, `web.md`, `features.md`.
- **Новые** — в `docs/contracts/collab.md`, до первого исполнителя:
  - сущности и мутаторы чата и документов;
  - видимость в синхронизации;
  - точки web: маршруты, боковая панель, `commands`, `taskPanels`;
  - формат push для сообщений.
- **Главный вопрос дизайна — видимость личных сообщений.** C-sync знает только два случая: «строка пространства» и «строка одного пользователя». Личный диалог на 2+ участников туда не помещается. Варианты:
  - расширить C-sync понятием «видимость канала» (members);
  - писать строку `changes` на каждого участника.

  Координатор выбирает простейший корректный вариант. Правка C-sync — версия +1, контрактный тест и проверка, что права в pull, bootstrap и WS по-прежнему соблюдаются (e2e на утечку). Это изменение существующего контракта, поэтому шлюз через главную.
- Индикатор «печатает…» — эфемерное WS-сообщение, не через `changes`. Это расширение протокола WS, тоже в контракт.

## 4. Правила среды
- Как в `docs/plan/core.md` §4 и `docs/plan/web.md` §4.
- Отчёт исполнителя — только в свою копию: `build/dpcli/<ID>.report.json`.
- Параллельно идёт модуль `work`. Общие файлы (`packages/shared`, `apps/api/src/sync`, `apps/web/src/sync`, `apps/web/src/layout`) — правим минимально. Регистрация модуля идёт через манифест, а не правкой ядра. Если правка ядра нужна — `contract:` координатору.
- На хосте порт 3000 занят. Стек поднимается с `API_PORT` (свой для каждой копии) и `COMPOSE_PROJECT_NAME`.

## 5. Задачи
- **CL-1 Чат: сервер.** `modules/chat`:
  - каналы пространства (публичные для участников пространства);
  - личные диалоги (2–8 человек);
  - сообщения: Markdown/TipTap JSON, упоминания, вложения через `/files`, правка и удаление своих, реакции (переиспользовать подход `commentReactions`);
  - треды через `parentId`;
  - метки прочтения (`lastReadSeq` на участника);
  - уведомления (упоминание, личное сообщение, ответ в треде) через хуки CR-7, push.

  Приёмка: права (не участник не видит), идемпотентность, push ставится в очередь, тест на утечку личных сообщений через pull, bootstrap и WS.
- **CL-2 Чат: интерфейс.**
  - раздел «Чат» в боковой панели: каналы, личные диалоги, счётчики непрочитанных;
  - лента с виртуализацией и подгрузкой истории;
  - редактор (тот же, что в комментариях WB-6) с упоминаниями и вложениями;
  - панель треда; «печатает…»; ссылка на задачу `PLN-123` раскрывается карточкой;
  - на mobile — экраны вместо панелей.

  Приёмка: 10 000 сообщений в канале прокручиваются без длинных кадров; отправка появляется ≤ 50 мс (оптимистично).
- **CL-3 Документы: сервер.** `modules/docs`:
  - страницы пространства: дерево через `parentId` + `rank`, заголовок, иконка, тело (ProseMirror JSON и текст для поиска);
  - связь страница ↔ задача;
  - мутаторы: создать, переименовать, переместить, архивировать;
  - мягкая блокировка: страница отмечена «редактирует X» с TTL. Шорткат: без совместного редактирования; если оно понадобится — Yjs и Hocuspocus.

  Приёмка: права, перемещение без циклов, архив вместе с поддеревом.
- **CL-4 Документы: интерфейс.**
  - дерево в боковой панели (перетаскивание);
  - редактор на TipTap: заголовки, списки, чек-листы, код, таблицы, изображения через `/files`, slash-меню, упоминание задач и людей;
  - блок «Документы» в карточке задачи (`taskPanels`);
  - локальный поиск по документам в Cmd+K;
  - индикатор блокировки.
- **CL-5 e2e.** Сценарии в `e2e/web`:
  - сообщение и упоминание доходят до второго пользователя вместе с push-уведомлением;
  - личный диалог невиден третьему;
  - документ создаётся, связывается с задачей и ищется через Cmd+K;
  - выключенный модуль скрывает раздел.

  Плюс замер бюджетов §7 — они не ухудшились.
