# Модуль features (FT)

## 1. Цель
Ярус A v1 из `docs/roadmap.md` §5.3: FT-1 пользовательские поля, FT-2 вид «Таблица», FT-3 вид «Календарь», FT-4 связи задач. Ярус B (FT-5…FT-8) в этот модуль не входит.

## 2. Решения пользователя
- Стек и принципы — `docs/roadmap.md` §1–§2. Простота: не перегружать интерфейс.
- В `main` ничего не сливаем без одобрения пользователя.
- Модуль стартует до шлюза MVP, параллельно с доводкой web. Срок жёсткий: около 6 ч.

## 3. Контракты
- **Потребляем:** `docs/contracts/core.md` (C-schema, C-mutators, C-modules, C-http), `docs/contracts/core-mutators.md`, `docs/contracts/web.md` (C-ui, C-client, C-tasks, C-views).
- **Новые стыки** — в `docs/contracts/features.md`, до первого исполнителя:
  - типы пользовательских полей и их значения в `tasks.fields`;
  - определения полей (сущность и мутаторы);
  - сущность связей и её мутаторы;
  - регистрация видов «Таблица» и «Календарь» через точку `views` из C-views.
- Правки в `packages/shared` и `apps/api` делаем здесь, но только расширяем: схема и мутаторы core меняются версией +1 с контрактным тестом. Существующее не ломаем.
- Нужна правка C-client или C-tasks web — это шлюз через главную. Модуль web сейчас меняет их в WB-18 (v3).

## 4. Правила среды
- Как в `docs/plan/core.md` §4 и `docs/plan/web.md` §4: тесты на `planar-testdb` со своей базой на прогон; строки интерфейса через i18n; начальный JS ≤ 200 КБ (новые виды — ленивыми чанками).
- **Параллельно с web WB-18** — не трогаем `apps/web/src/sync/`, `apps/web/src/tasks/`, `apps/web/src/views/list/`, `e2e/web/perf/`. Свежий `feature/web` забираем слиянием в `feature/features`.
- **Файл отчёта исполнителя** — уникальный, в своей копии: `build/dpcli/<ID>.report.json`. Общий `/tmp/.../r.json` не использовать.

## 5. Задачи
Оценки — `docs/roadmap.md` §5.3.
- **FT-1 Пользовательские поля.** 7 типов: текст, число, дата, выбор, пользователь, ссылка, деньги. Определения полей на уровне проекта; значения в `tasks.fields`; мутаторы с валидацией по типу; UI в карточке задачи (точка `taskPanels` или блок полей); фильтры по полям в сохранённых видах; REST и MCP отдают поля. Приёмка: тесты мутаторов на каждый тип, неверное значение отклоняется, удаление определения не ломает задачи.
- **FT-2 Вид «Таблица».** Колонки: системные поля и пользовательские (FT-1); ширина и порядок колонок; инлайн-правка; массовая правка выделенного; виртуализация строк. Приёмка: 10 000 задач без подвисаний, правка ячейки через мутатор.
- **FT-3 Вид «Календарь».** Месяц и неделя по `due`/`start`; перетаскивание меняет даты; задачи без даты — в боковой колонке; на mobile — список по дням. Приёмка: перенос даты через мутатор, корректная граница дня по часовому поясу пользователя.
- **FT-4 Связи задач.** Блокирует, заблокирована, связана, дубликат: одна строка на пару, обратная сторона вычисляется. Блок в карточке задачи; поиск задачи для связи; иконка «заблокирована» в Списке и на Доске (только чтение данных, без правки `views/list` до слияния WB-18 — иначе после). Приёмка: нельзя связать задачу с самой собой, дубль пары отклоняется, удаление задачи чистит связи.

## 6. Волны
- Контракты → FT-1 ‖ FT-3 ‖ FT-4 → FT-2. FT-2 зависит от FT-1; каркас колонок можно начать раньше.
- Не больше 4 исполнителей одновременно.
- После модуля — e2e-сценарий на каждый вид в `e2e/web`.
