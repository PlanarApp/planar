# Модуль chatai — личный чат с ИИ: полный доступ

## 1. Цель
PLNRAPP-210. В личном чате ИИ отвечает по документации Planar, сам настраивает систему (правила и автоматизации, метки, статусы, поля, ИИ-действия, harness-пакеты и привязки событий, проект и модули) и массово обрабатывает задачи. Всё — от имени того, кто просит, и с его правами: чего не может пользователь, того не может и ИИ.

Есть: чат-прогон получает инструменты реестра MCP (`apps/api/src/mcp/tools.ts`) с правами автора сообщения; опасные действия ждут «да» (`modules/ai/api/chat-tools.ts`, `needsConfirmation`); `generateReply` — жёсткий `stepCountIs(5)`, лимита токенов нет.

## 2. Решения пользователя (ответы в PLNRAPP-210, 2026-11-13; исполнитель — эта сессия, 2026-11-16)
- Разбить на подзадачи (а–д) — заведены PLNRAPP-266…270.
- Пакеты harness (`api/ai/packs`, `api/ai/harness`): снять ограничение «только из сессии» для админа проекта с токеном на запись. Секретные настройки ИИ (подключения с ключами, лимиты) — по-прежнему только из сессии.
- «Справку модулей» не пишем: источник документации — `docs-site/` (ru, en); документы проекта уже доступны через `list_docs`/`get_doc`.
- Настройки модулей: ИИ только включает и выключает модули (`project.setModule`) и меняет поля проекта (`project.update`); настройки с секретами (подключения ИИ, GitLab, почта, вебхуки, лимиты ИИ) не трогает.
- Подтверждение «да»: на все изменения настроек (создание, изменение, удаление правил, ИИ-действий, статусов, меток, полей, пакетов, событий, модулей, проекта) и на все пачечные операции — со списком того, что будет изменено. Без подтверждения — только чтение и поиск.

## 3. Задачи (подзадачи Planar)
Разбивку на карточки и волны делает координатор по коду. Каждая новая функция REST v1 — в той же задаче инструмент MCP, строка `PARITY` в `apps/api/test/mcp/mcp.test.ts` и тест.
- **(а) PLNRAPP-266** — REST/MCP настройки поверх существующих мутаторов: статусы, метки, поля (CRUD), автоматизации (CRUD), ИИ-действия, `project.update`, `project.setModule`. Права — `executeMutations`.
- **(б) PLNRAPP-267** — поиск и чтение разделов `docs-site/` (ru, en) инструментом, не весь текст в промпте; `docs-site` в образ api (Dockerfile).
- **(в) PLNRAPP-268** — поиск задач с фильтрами и пачечное изменение (статус, метки, исполнители, поля, архив); в чате — одно «да» на пачку со списком изменений.
- **(г) PLNRAPP-269** — пакеты (загрузка, diff, apply) и привязки событий в REST/MCP; снять «только из сессии» для админа проекта с токеном на запись.
- **(д) PLNRAPP-270** — `needsConfirmation` по решению выше; лимиты шагов и токенов чат-прогона переменными окружения (в `.env.example`, контракт ops-env); инструкция «Чат» (`chat.md`) во всех пакетах под новые возможности.
- Контракты (`docs/contracts/*`), CHANGELOG, `docs-site/` (что умеет ИИ в чате), демо-сид `apps/api/src/db/seed-demo.ts` (личный чат с примером настройки через ИИ, если это видно в демо).

## 4. Приёмка волн и доставка
- После влития каждой волны в `feature/chatai` — проверки как в CI на ветке модуля: `pnpm --filter "@planar/api..." --filter "@planar/ai-runner" build` и `pnpm -s lint`; красное исправлять в этой волне. Новая зависимость — в scope карточки вместе с `package.json` и `pnpm-lock.yaml`. Новая миграция — `when` в `apps/api/drizzle/meta/_journal.json` больше последнего.
- Перед deliver: полный `pnpm test`; `git fetch origin main` — если main ушёл вперёд, обновить `mr/PLNRAPP-210` и `.dpcli/dpcli sync chatai`; `.dpcli/dpcli deliver chatai --into mr/PLNRAPP-210`; `chatai done`. Пуш и MR делает главная сессия.

## 5. Условия остановки
- Снятие «только из сессии» задевает что-то кроме пакетов и привязок событий (подключения, ключи, лимиты) — вопрос пользователю.
- Нужен инструмент, который меняет настройки с секретами, или права ИИ шире прав пользователя — вопрос пользователю.
