# Модуль ai10 — Runner (runtime=agent)

## 1. Цель
PLNRAPP-176: запуск agent-действий в изолированном контейнере. Источник: `/root/planar-ai10/build/ai-plan.md` «### 5. Runner», «Решения» (docker-socket-proxy по меткам не фильтрует — поэтому свой узкий сервис). Не входит: сборка образа из Dockerfile клиента, harness-пакет с agent-действиями (ИИ-11), GitLab-токен для push/MR.

## 2. Решения (2026-11-12, coordinator, пользователь спит)
- Сервис `ai-runner` — отдельный Node-пакет `apps/ai-runner` (без Nest, `node:http`, docker Engine API по unix-сокету через `node:http`; без новых зависимостей). Единственный, кто видит `/var/run/docker.sock`. Слушает только внутреннюю сеть `runner`, общий секрет `AI_RUNNER_TOKEN` (Bearer).
- Контракт api ↔ runner и api ↔ контейнер — `docs/contracts/ai10.md` v1.
- Контекст задачи — поле `context` (строка) в вызове runner'а; runner кладёт его в `/context/context.json` через `putArchive` в `/` после create (не в tmpfs) (binds запрещены). Размер ≤ 1 МБ.
- Сети: `runner` (api ↔ ai-runner), `agents` (контейнеры агентов ↔ squid ↔ api; internal: без выхода наружу). Squid — единственный выход в интернет, allowlist доменов в конфиге. Агент ходит в LLM-прокси api по `http://api:3000/api/ai/llm/:runId`; api подключён к `agents` второй сетью.
- Миграция — 0057 (0055, 0056 заняты MR !164): колонки в `ai_runs` (agent_secret_hash, container_id, heartbeat_at, started_at) и `ai_project_limits.max_agents`. Если ai10 доставляется после слияния !164 — порядок и снапшот пересобрать.
- Лимиты реплик: инстанс — env `AI_AGENT_MAX_REPLICAS` (по умолчанию 2), проект — `ai_project_limits.max_agents` (null — только инстанс). Превышение: воркер перепланирует job с `startAfter` 30 с, пока не освободится место.
- Воркер pg-boss только стартует контейнер и возвращается; завершение — `POST /api/ai/runs/:id` с секретом прогона или «жнец» (cron, раз в минуту): `running` agent-прогон без heartbeat > 2 мин (или дольше `AI_AGENT_TIMEOUT_MIN`, 60) → runner `DELETE`, прогон `failed`.
- Ключ провайдера в контейнер не передаётся; секрет прогона одноразовый: в БД только sha256, действует, пока прогон `running`.
- Образ по умолчанию `planar-ai-agent` — Dockerfile в `docker/ai-agent/`; локально НЕ собираем (диск хоста).
- Демо-сид не трогаем: видимых пользователю изменений нет.
