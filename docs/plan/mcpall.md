# Модуль mcpall — полное управление инстансом через MCP

## 1. Цель
Собственный ИИ полностью управляет инстансом Planar через его MCP: закрыть пробелы «в интерфейсе есть, в MCP нет» (около 50 возможностей, найдены в aikb, KB-9).

## 2. Решения пользователя (из PLNRAPP-271)
- Каждая новая функция — REST v1 (`apps/api/src/rest`) + инструмент MCP (`apps/api/src/mcp/tools.ts`), строка `PARITY` (`apps/api/test/mcp/mcp.test.ts`) и тест.
- Права — от имени пользователя через существующие мутаторы; новый мутатор — только где его нет.
- В чате ИИ — подтверждение «да» на изменения и удаления (как в PLNRAPP-270); удаления — `danger`.
- Знания aikb строятся из реестра: новые инструменты попадают в них сами; тест полноты aikb требует описания каждого инструмента.
- Исключено: настройки с секретами (подключения ИИ, SMTP/IMAP, подключения GitLab, секреты вебхуков в ответах); вход под другим пользователем, push-подписки, облако, плагины; выпуск и отзыв API-токенов.

## 3. Задачи (подзадачи Planar)
Разбивку на карточки и волны делает координатор по коду; одна подзадача — одна или несколько карточек. Файлы REST/MCP общие (`tools.ts`, `PARITY`, openapi) — параллельные карточки дописывают в разные места или в отдельные файлы инструментов по образцу `apps/api/src/mcp/tools-kb.ts`, чтобы не конфликтовать.
- **PLNRAPP-272** — пространства (create/update/delete), проекты (create с ключом, шаблоном, модулями; delete; copy_project_dictionaries; архив в update_project), режим участников и участники проекта с ролями, участники пространства и роли, пользователи инстанса (только админ инстанса), модули инстанса и имя workspace.
- **PLNRAPP-273** — задачи: delete/restore/merge, watch/unwatch, чек-листы, вложения (base64 или URL, лимит размера), реакции, удаление комментария, лента активности задачи.
- **PLNRAPP-274** — сохранённые виды и вид по умолчанию, избранное, «Мой день», уведомления.
- **PLNRAPP-275** — циклы (configure/create/update/delete/close, задача в цикл), цели, ключевые результаты, вехи, время (правка, удаление, оценка, отчёт), нагрузка, повторяющиеся задачи.
- **PLNRAPP-276** — шаблоны (и задача/проект из шаблона), формы (и ссылка), дашборды и виджеты.
- **PLNRAPP-277** — документы: перенос, архив, восстановление, удаление, блокировка, версии, правка/удаление/назначение комментариев страницы, снятие ссылки документ-задача.
- **PLNRAPP-278** — чат: каналы и личные чаты, участники, mute, сообщения (чтение, отправка, правка, удаление, реакции), прочтение; читать только доступные пользователю каналы.
- **PLNRAPP-279** — журнал прогонов автоматизаций, вебхуки без секретов (подписки, ping, доставки, повтор), импорт (preview, запуск, статус), личные почтовые предпочтения, ветка и MR GitLab из задачи по существующему подключению.
- CHANGELOG (одна запись на модуль). Демо-сид не нужен (функции не видны в интерфейсе).

## 4. Приёмка волн и доставка
- Волна — до 4 исполнителей; после каждой волны — полный `pnpm test` и `pnpm -s lint` из корня копии модуля.
- Тест на каждый новый путь: права (чужой пользователь получает отказ), `danger` у удалений, строка `PARITY`.
- Доставка — `deliver mcpall --into mr/PLNRAPP-271`, MR `PLNRAPP-271: …` с автомержем после CI.
## 6. Разбивка на карточки и волны
Контракт — `docs/contracts/mcpall.md` (C-ext v1): каждая область — свой файл `apps/api/src/rest/ext/<area>.ts` и свой тест `apps/api/test/mcp/ext-<area>.test.ts`, общие файлы правит только каркас.
- **Волна 1:** MA-1 каркас (ExtOp, регистрация в REST/OpenAPI/MCP/чате, заглушки всех областей, тест PARITY) → после слияния параллельно: `spaces` (272: пространства, проекты, участники, роли), `tasks` (273 без вложений), `views` (274).
- **Волна 2:** `instance` (272: пользователи инстанса, модули, workspace; только админ), `attachments` (273; ревью), `planning` (275: циклы, цели, KR, вехи), `time` (275: время, нагрузка, повторяющиеся).
- **Волна 3:** `templates` (276), `forms` (276: формы, дашборды), `docs` (277), `chat` (278; ревью).
- **Волна 4:** `integrations` (279: журнал автоматизаций, вебхуки, импорт), `mailgit` (279: почтовые предпочтения, ветка и MR GitLab), CHANGELOG.
- Ревьюер — по риску: права, вложения, пользователи инстанса, чат, вебхуки.

## 5. Условия остановки
- Функции нужен новый мутатор с изменением схемы БД или синхронизации — вопрос пользователю.
- Функция касается исключённого списка (секреты, токены, облако, плагины) — не делать, вопрос.
- Падение чужих тестов, не связанное с модулем, — блокер одной строкой.
