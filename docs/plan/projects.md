# Модуль projects (PJ)

## 1. Цель
Перенести настройку работы в проект: статусы, метки и модули задаются в проекте, а не в пространстве или Workspace. Вид и фильтры узла сохраняются на сервере для каждого пользователя. Попутно — дефекты списка, обновления PWA и мелочи UI из списка пользователя от 2026-11-02.

## 2. Решения пользователя (2026-11-02)
1. **Модули.** Модули с данными проекта (gitlab, sprints, time, forms, recurring, automations, templates, goals, timeline, workload, dashboards, docs) включаются галочкой в настройках проекта. Общие модули (chat, email, plugins, import, webhooks) остаются на уровне экземпляра: их включает админ экземпляра на отдельной странице, не в настройках Workspace. Раздела «Модули» в настройках Workspace больше нет.
2. **Статусы и метки — в проекте.** Миграция копирует статусы и метки пространства в каждый его проект и перепривязывает задачи. В сводных списках (пространство, папка, «Моя работа») группировка и фильтр — по имени статуса или метки и по категории статуса; одинаковые имена из разных проектов сливаются. Новый проект может скопировать статусы и метки из другого проекта того же пространства.
3. **Вид узла.** Личный поверх общего: изменения фильтров и вида сохраняются на сервере сразу и лично для пользователя по каждому узлу. Кнопка «Сохранить для всех» остаётся и задаёт вид по умолчанию; «Сбросить» возвращает к общему.
4. **Процесс.** Модуль с координатором и исполнителями (sonnet, до 4 параллельно), запуск из новой сессии.
- **Новый проект создаётся с модулями, включёнными у админа экземпляра (по умолчанию включены, в проекте можно выключить)** (2026-11-02)
- **Сводные виды (пространство, папка, «Моя работа») и вкладка «Документы» показывают модуль, если он включён хотя бы в одном проекте — оставить так** (2026-11-02)
- **PJ-12: промежуточное состояние «у части задач» в массовой панели не нужно — первый клик назначает всем, второй снимает со всех** (2026-11-02)
- **PJ-11: админ пространства и админ экземпляра видят проект всегда, даже если убраны из его участников** (2026-11-03) — иначе возможен проект, который не видит ни один администратор
- **Визуальные снимки (35 расхождений PJ-31) — ожидаемые изменения, эталоны обновить** (2026-11-03)
- **Итоговые эталоны снимков (39 изменений против main, PJ-36/PJ-37) одобрены; финальный прогон на чистой БД, при зелёном — deliver** (2026-11-03)
- **Перед доставкой изолировать visual.spec от данных других e2e и переснять эталоны (вариант 1); тестовые стеки задач удалить** (2026-11-03)

## 3. Задачи
Детали интерфейса и данных — в контрактах координатора; здесь — поведение и приёмка.

- **PJ-1 Статусы и метки в проекте (сервер, shared).**
  - Сущности статусов и меток принадлежат проекту; мутаторы, проверки принадлежности (статус задачи — из её проекта), REST v1 и MCP — по проекту.
  - Миграция по решению 2.2: копии в каждый проект пространства, задачи и связи меток перепривязаны, ничего не теряется; строки синхронизации доходят до клиентов (изменения через `changes`, не молчаливый SQL по синхронизируемым таблицам — либо явное обоснование в контракте).
  - Копирование статусов и меток из другого проекта того же пространства — мутатор.
  - Модули, ссылающиеся на статусы пространства (gitlab `mergedStatusId`, automations, forms, recurring, templates и др.), — по проекту.
  - Приёмка: тесты миграции на данных с несколькими пространствами и проектами; контрактные тесты; полный vitest.
- **PJ-2 Статусы и метки в проекте (web).**
  - Разделы «Статусы» и «Метки» — в настройках проекта, из настроек пространства убраны; копирование из другого проекта пространства.
  - Выбор статуса и метки в задаче — из её проекта; сводные списки по решению 2.2 (группировка, фильтр, порядок колонок по категории).
  - Приёмка: vitest web, e2e на настройки проекта и сводный список с двумя проектами.
- **PJ-3 Модули в проекте.**
  - Включение модуля для проекта (сервер, синхронизация, права — админ проекта/экземпляра по контракту); проектные элементы модуля (панели задачи, вкладки, разделы настроек, задания опроса) работают только в проектах, где модуль включён.
  - Общие модули — отдельная страница админа экземпляра; раздел «Модули» из настроек Workspace убран.
  - Миграция: модуль, включённый для экземпляра, включён во всех существующих проектах.
  - Приёмка: vitest api/web, e2e: модуль включён в одном проекте и не виден в другом.
- **PJ-4 Личный вид узла на сервере.**
  - Фильтры и вид (колонки, группировка, сортировка, тип вида) по решению 2.3; работает на всех уровнях узлов (проект, папка, пространство, «Моя работа»), переживает перезагрузку и другой браузер.
  - Приёмка: vitest, e2e: два пользователя видят каждый свой вид; «Сбросить» возвращает общий.
- **PJ-5 Создание метки из поля назначения.** Если введённой метки нет — пункт «Создать «…»» в выборе меток задачи; метка создаётся в проекте задачи и сразу назначается. Зависит от PJ-1/PJ-2.
- **PJ-6 Выбор эмодзи в настройках узла.** Справа от поля ввода эмодзи — кнопка выбора; компонент выбора — тот же, что в чате (переиспользовать, при необходимости вынести в общий UI).
- **PJ-7 Обновление PWA.** Клик «Обновить» при пришедшем обновлении сейчас ничего не делает — найти причину и исправить; во время загрузки новой версии показывать прогресс, после — перезагрузка в новую версию. Приёмка: e2e с подменой версии service worker.
- **PJ-8 Вид «Список».**
  1. Включённые поля показываются и когда значение пустое (пустая ячейка, а не скрытая колонка).
  2. Поле «Проект» показывает имя проекта, а не папку. Воспроизведение (пользователь, 2026-11-02): мобильный, вид «Список», поле «Проект» включено — под задачей в мобильной карточке выводится папка вместо имени проекта.
  3. В списке не-проекта (пространство, папка, «Моя работа») поле «Проект» включено по умолчанию.
- **PJ-9 Мобильный переход в задачу без потери списка.** На мобильном открытие задачи из списка, таблицы или доски и возврат назад сохраняют состояние вида (прокрутка, раскрытые группы, фильтры); на десктопе уже работает. Вариант — открывать задачу в полноэкранном диалоге поверх вида. Приёмка: e2e в мобильном viewport: прокрутка → задача → назад → та же позиция и состояние.
- **PJ-10 Вёрстка «Моей работы» на мобильном.** Весь раздел «Моя работа» на мобильном выходит за границы: страница целиком прокручивается и по x, и по y (должна прокручиваться только область списка, как в «Задачах»); панель фильтра открывается за пределами экрана. В списке «Задачи» всё в порядке — выровнять по нему. Приёмка: e2e в мобильном viewport на всех вкладках/видах «Моей работы»: у документа нет прокрутки ни по x, ни по y, панель фильтра в пределах экрана.
- **PJ-11 Участники в настройках проекта.** Раздел «Участники» в настройках проекта: по умолчанию состав и роли наследуются из пространства, в проекте их можно перекрыть (добавить, убрать, сменить роль); права доступа к проекту следуют итоговому составу. Детали наследования и синхронизации — в контракте координатора. Приёмка: vitest api/web, e2e: участник, убранный из проекта, не видит его задач; без перекрытия состав совпадает с пространством.
- **PJ-12 Снятие назначения в массовых операциях.** Если в массовом выборе исполнителей (и других множественных полей) снять отметку, значение снимается со всех выбранных задач; сейчас операция только добавляет. Приёмка: vitest, e2e: снять исполнителя с нескольких задач разом.
- **PJ-13 Упоминания задач и документов в комментариях.** `@@` открывает выбор задачи, `@@@` — выбор документа; раньше работало, сейчас нет — найти причину регрессии и исправить. Приёмка: e2e на оба упоминания в комментарии.
- **PJ-14 Модули нового проекта по умолчанию.** По решению пользователя (2026-11-02): новый проект создаётся с модулями, включёнными у админа экземпляра; в проекте их можно выключить. Приёмка: vitest api, e2e: созданный проект сразу показывает включённый модуль.
- **PJ-15 Возврат в «Мою работу» на мобильном.** «Моя работа» открывает задачу так же, как остальные списки (полноэкранно поверх вида, PJ-9); после возврата прокрутка и состояние вида сохраняются. Приёмка: e2e в мобильном viewport в «Моей работе».
- **PJ-17 Старые клиенты не получают данные после обновления (критично).** Случай пользователя: клиент с локальной репликой, созданной до обновления ветки, показывает пусто, новый клиент — данные есть; после очистки данных сайта в старом клиенте данные появляются. Найти причину (вероятно, сброс реплики `_reset` / epoch из миграций PJ-1, PJ-3, PJ-11 или смена схемы реплики) и исправить так, чтобы существующий клиент сам догонял состояние без очистки данных. Приёмка: тест/e2e: клиент с репликой до миграции после обновления видит те же данные, что новый. Ревью — dp-reviewer.
- **PJ-18 Ширина сайдбара.** Сайдбар можно тянуть по ширине мышью; ширина запоминается (личная настройка); есть минимум и максимум.
- **PJ-19 Ширина боковой формы задачи.** Боковая панель задачи тянется по ширине так же, ширина запоминается.
- **PJ-20 Свёрнутый сайдбар на десктопе.** Сайдбар сворачивается в узкую полосу с иконками/ключами проектов или скрывается полностью; состояние запоминается, развернуть можно в один клик.
- **PJ-21 Кнопки «Сохранить/Сбросить» вида не сдвигают меню.** Появление кнопок при изменении вида не меняет положение меню «Вид» (место зарезервировано или кнопки встают с другой стороны).
- **PJ-22 Выделить все задачи.** Сейчас задачи в списке выделяются только по одной; нужен выбор всех разом (чекбокс «выбрать все» в заголовке, на группу — по группе) для массовых операций.
- **PJ-23 Возврат на вид «Список».** В «Задачах» после ухода со «Списка» на любой другой вид клик по «Список» его не открывает — исправить.
- **PJ-24 Прокрутка доски перетаскиванием на десктопе.** Доску можно тянуть по горизонтали мышью за пустое место (без конфликта с перетаскиванием карточек).
- **PJ-25 Фильтры без текстовой строки.** Выбранные фильтры не выводятся текстом под панелью; кнопка фильтра показывает, что фильтр не пуст (отметка), а подсказка на ней — список активных фильтров.
- **PJ-29 «Выбрать все» в сгруппированном списке.** Доработка PJ-22 (решение пользователя 2026-11-03): выбор всех задач в заголовке и по каждой группе работает и при группировке (по умолчанию список сгруппирован по статусам). Приёмка: vitest, e2e на сгруппированном списке: выбрать группу, выбрать все.
- **PJ-30 Вернуть меню «Колонки» в таблице.** Решение пользователя 2026-11-03: меню «Колонки» (убрано в 3bbe327f) вернуть; через него показываются и скрываются колонки, в том числе «Дата начала» и пользовательские поля; выбор хранится в виде (PJ-4). Тест table.test.ts, утверждающий отсутствие кнопки, — обновить. Приёмка: vitest, e2e: включить колонку «Дата начала» и пользовательское поле.

## 6. Условия остановки (шлюз главной)
- Миграция PJ-1 или PJ-3 не может сохранить данные без потерь или без доставки изменений клиентам.
- Изменение контракта задевает модули вне перечисленных в задаче.
- Сводные списки по решению 2.2 не укладываются в бюджеты производительности списка.
- Причина дефекта PJ-7 — вне `apps/web` (сборка, Caddy, заголовки кеша).
