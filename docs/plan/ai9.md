# ai9 — ИИ в чате

## 1. Цель
Источник: PLNRAPP-175, `/root/planar-ai9/build/ai-plan.md` (блок «ИИ в чате» стр. 104–113, §4 «Флоу прогона»). В main уже: `modules/ai` (ai_runs, `ai.run`, бот `ai`, лимиты/выключатель, harness и инструкция «Чат» пакета «Разработка»). Бот отвечает в личном чате и в групповом при цитировании, действует инструментами MCP с правами инициатора.

## 2. Решения (coordinator, пользователь спит)
- D1. Миграция — 0055, только если нужна (0054 занята `ai_email_batches` в !163). Если для чата хватает существующих таблиц — не создаём.
- D2. Письма из чата — через пачку !163: если !163 не в main к моменту задачи, письма вне объёма (в «не сделано»); инструмент отправки писем в чате не отдаём.
- D3. Один список инструментов на MCP и чат: `tools.ts` рефакторится так, чтобы определения (имя, описание, zod-схема, `write`, функция от `(rest, uid)`) жили в одном реестре; `buildMcpServer` регистрирует из него, чат строит tools AI SDK из него же. Поведение MCP не меняется (PARITY-тест зелёный).
- D4. Права инициатора: все вызовы через `RestService` с `uid` инициатора (не бота). Мутации — `origin.aiRunId`; в activity «Имя (через ИИ)» (механизм уже есть для прогонов, не дублировать). Бот сам права не расширяет.
- D5. Реакция на чат — shared-хук/событие модуля `chat` (личные чаты без `projectId` могут быть не видны `afterMutation` data-модуля ai, см. `mutate.ts:50-66`; исполнитель сначала проверяет факт и выбирает минимальный способ). Триггер: сообщение человека (не бота) в личном канале с ботом — всегда; в групповом — только reply в тред на сообщение бота либо `ai` в `mentions`. Остальные сообщения бот читает как контекст (последние N сообщений и треды), не отвечая. Инициатор = автор процитировавшего сообщения.
- D6. Подтверждение: массовые изменения (> `CHAT_BULK_LIMIT = 5` задач за запрос), любое удаление и письма — бот сначала перечисляет план действий в ответе и ничего не выполняет; выполняет после «да» (и синонимов) автора запроса в том же треде. Ожидание подтверждения хранится в данных (сообщения/состояние прогона), не в памяти процесса: рестарт не теряет и не выполняет без «да». «Да» от другого человека не считается.
- D7. Прогоны чата — строки `ai_runs` (kind `chat`): лимиты, выключатель и бюджет как у прочих прогонов. `taskId` у чата может быть пуст — проверить схему, при необходимости миграция 0055 (`task_id` nullable + `channel_id`), снапшот включает 0052–0054, после правки снапшотов — prettier.
- D8. Промпт — инструкция «Чат» активного пакета проекта (если канал привязан к проекту), иначе общая инструкция инстанса (константа в `modules/ai`). Ответ — текст сообщения, действия — вызовы tools.
- D9. REST v1 и набор MCP не меняются (новых функций нет) → PARITY не трогаем.

## 3. Задачи и волны
- Волна 1 (параллельно, скоупы не пересекаются):
  - **AIC-1** Реестр инструментов: рефакторинг `apps/api/src/mcp/tools.ts` в общий реестр + адаптер в tools AI SDK (`modules/ai/api/chat-tools.ts`), контекст инициатора, `origin.aiRunId`, пометка опасных (удаление/массовые/письма) для D6. Тесты: MCP не изменился; tools вызывают RestService от uid инициатора; права (нет доступа → отказ, без эскалации).
  - **AIC-2** Реакция на чат: хук модуля chat → постановка `ai.run` kind `chat`; правила личный/групповой (D5), контекст N сообщений; ответ сообщением бота в канал/тред (пока текст LLM без инструментов). Миграция 0055 — здесь, если нужна.
- Волна 2: **AIC-3** Сборка: прогон `chat` вызывает LLM с tools из AIC-1 от инициатора, подтверждение «да» (D6), промпт (D8), тесты прав (групповой: права процитировавшего; отказ с пояснением), демо-сид `apps/api/src/db/seed-demo.ts` (личный и групповой чат с ботом, подтверждение) + `apps/api/test/seed-demo.test.ts`.
- Последняя волна: полный `pnpm test` + `pnpm -s lint`, `deliver ai9 --into mr/PLNRAPP-175`, уборка, `ai9 done`.
- Ревьюер: один `dp-reviewer` на AIC-3 (права инициатора — риск эскалации); AIC-1 и AIC-2 — по отчёту.

## 4. Стоп-условия
Права инициатора нельзя провести через RestService без обхода; хук chat не видит личные чаты без изменения контракта chat — решение координатора (`decide --by coordinator`), без обхода прав.
