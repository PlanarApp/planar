# ai5 — ИИ-диалог по документу и визард

## 1. Цель
Источник: PLNRAPP-170, `/root/planar-ai5/build/ai-plan.md` (§6 стр. 189–226, «ИИ-диалог по документу» стр. 201; «### 8. Визард» стр. 300–309). В main уже: `modules/ai` (подключения, прогоны, мониторинг), `/api/ai/harness/{diff,apply}`, `/api/ai/packs` (list, upload с `resolve` reset/keep/merged, merge, activate, export), пакет «Разработка», `docPanels` (панель документа, `HarnessPanel.vue`), чат с ботом.

## 2. Решения (coordinator, пользователь спит)
- D1. Миграция не нужна (диалог без хранения истории на сервере: история — состояние панели; прогон `ai_runs` не создаём, вызов `generateStructured` как в merge у `packs.controller`). Если понадобится — 0058 (0057 занята !165), решать через `decide`.
- D2. Диалог по документу: `POST /api/ai/doc-chat {pageId, message, history[]}` → `{reply, proposal?: {body, baseUpdatedAt, diff}}`. ИИ возвращает полный новый текст документа; diff считает сервер. Права: доступ на запись в документ как у обычной правки страницы, иначе 403.
- D3. «Принять» = read-modify-write: запись через штатный мутатор docs (не прямой SQL) с проверкой версии: если `updatedAt` страницы != `baseUpdatedAt` — 409, панель предлагает перегенерировать правку. Чужие правки не затираются молча.
- D4. Для документа пакета (страница под «Harness-пакеты» проекта) в контекст добавляются статусы проекта и правила, страница `harness.yml` — как есть; применение структуры остаётся кнопкой «Применить harness».
- D5. REST v1 не меняется (внутренний `/api/ai/*`, как packs/harness) → MCP/PARITY не трогаем.
- D6. Визард — компонент в Настройки → ИИ поверх существующих packs/harness API: 1 ключ + «проверить связь» (эндпоинт проверки, если аналога нет), 2 выбор шаблона из `modules/ai/harnesses/` (сейчас только «Разработка») с редактируемым промптом настройки, 3 ИИ адаптирует пакет под проект и раскладывает в документы, 4 diff harness → «Применить». Шаг 5 (harness-retro, PLNRAPP-178) пропущен.
- D7. «Переинициализировать» = тот же визард; при изменённых страницах — «Сбросить / Оставить мои / Объединить» через существующие `upload` с `resolve` и `merge`.
- D8. i18n ru/en, демо-сид `apps/api/src/db/seed-demo.ts` + `apps/api/test/seed-demo.test.ts`.
- D9. Перед deliver: `git fetch origin main`; main ушёл вперёд — fast-forward базы mr/PLNRAPP-170 до origin/main + `dpcli sync ai5`, порядок миграций, prettier на снапшоты.

## 3. Задачи и волны
- Волна 1 (параллельно, скоупы не пересекаются):
  - **AID-1** API диалога по документу (D2–D4): эндпоинт, diff, контекст пакета, apply с проверкой версии (D3). Тесты: предложение, принятие, 409 при чужой правке, нет прав, контекст пакета.
  - **AID-2** Web: панель «ИИ-диалог» через `docPanels` для любого документа (чат, diff, «Принять»/«Отклонить», обработка 409), убрать чат/редактор пакета из настроек (если есть), i18n. Формат ответа AID-1 — в `task note`.
- Волна 2: **AID-3** визард (D6–D7) в Настройки → ИИ, проверка связи, переинициализация, i18n, демо-сид + тест сида.
- Последняя волна: полный `pnpm test` + `pnpm -s lint`, `deliver ai5 --into mr/PLNRAPP-170`, уборка, `ai5 done`.
- Ревьюер: один `dp-reviewer` на AID-1 (read-modify-write может затереть чужие правки); остальное — по отчёту.

## 4. Не сделано (заранее)
Шаг 5 визарда (harness-retro, PLNRAPP-178); шаблоны Продажи/Найм/Поддержка (PLNRAPP-174) — визард показывает каталог как есть.

Запись документа нельзя провести через штатный мутатор с проверкой версии; визарду нужна миграция — решение координатора (`decide --by coordinator`).
