# Модуль p3 (PT)

## 1. Цель
Функции фазы 3 (`docs/roadmap.md` §11). Каждая — модуль `modules/<id>` по C-modules (включается и выключается), кроме совместного редактирования: оно меняет редактор ядра и модуль docs.

## 2. Решения пользователя (2026-10-24)
- Берём: совместное редактирование, Timeline/Gantt и Workload, дашборды и формы, GitLab.
- ИИ не делаем — достаточно MCP.
- GitLab: сервер сам опрашивает GitLab API по расписанию. Без вебхуков и без glab.
- Визуал — модуль `design`. Новые экраны строятся на C-ui v3.
- В `main` — только с одобрения пользователя.

## 3. Контракты (`docs/contracts/p3.md`, до первого исполнителя)
- **Потребляем:** `docs/contracts/core.md` (+ части), `work.md`, `work-api.md`, `collab.md`, `features.md`, `web.md`. C-ui v3 пишет `design` (DS-0). До него интерфейс строим на текущих компонентах и переводим после.
- **Новое:**
  - **collab-протокол:** WS `/collab` Hocuspocus, авторизация по cookie и правам на документ.
  - **Хранение Yjs и проекция.** Состояние Y.Doc хранится в `ydocs(doc_id, state bytea, updated_at)`. При сохранении (debounce) из него пересобираются ProseMirror JSON и текст в существующие поля (`docsPages.body`, `tasks.description`). Тогда синхронизация, поиск, REST и MCP работают как раньше.
  - **Сущности и мутаторы** модулей timeline, workload, dashboards, forms, gitlab.
  - **Публичный эндпоинт форм.**
- **Владелец C-modules и прочих C-\*** — главная. Нужна правка — строкой `contract: …` главной, а не своей версией (урок фазы 2: две параллельные v4 и v5).

## 4. Задачи
- **PT-0 Разбить `docs/contracts/core.md`.** Сейчас он больше 40 КБ, и `docs check` в main падает. Разделы-файлы со ссылками; контрактный тест `packages/shared/test/contract.test.ts` и `versions.ts` должны проходить. Механическая задача, `dp-mechanic`.
- **PT-1 Совместное редактирование.**
  - Зависимости: `yjs`, `y-prosemirror` через `@tiptap/extension-collaboration` и `collaboration-cursor`, `@hocuspocus/server`, `@hocuspocus/provider`, `y-indexeddb` (офлайн). Выбраны пользователем: «Yjs + Hocuspocus».
  - Сервер: Hocuspocus в процессе api, на пути `/collab` того же HTTP-сервера; `onAuthenticate` — сессия и право на документ (страница docs или задача).
  - Хранение и проекция — по §3.
  - Клиент: документы docs и описание задачи на Collaboration; курсоры с именем и цветом участника; офлайн через y-indexeddb, догон при подключении.
  - Мягкая блокировка docs (CL-3) убирается. Миграция существующих тел: Y.Doc создаётся из текущего JSON при первом открытии.
  - Приёмка:
    - два клиента одновременно правят один документ, оба видят изменения друг друга ≤ 500 мс;
    - офлайн-правка доходит после переподключения;
    - не участник пространства не может подключиться (тест на отказ);
    - проекция обновляет `body` и текст для поиска;
    - CL-3 и e2e документов зелёные.
- **PT-2 Timeline** (`modules/timeline`, вид проекта «Таймлайн»).
  - Полосы задач по `start`/`due`, масштаб день, неделя, месяц.
  - Перетаскивание меняет даты, растягивание — длительность.
  - Стрелки зависимостей по связям «блокирует» (F-links); при переносе блокирующей предупреждение о нарушении (без автосдвига).
  - Задачи без дат — в отдельной колонке, оттуда перетаскиваются на шкалу.
  - Виртуализация по строкам и времени. Приёмка: 10 000 задач без длинных кадров.
- **PT-3 Workload** (`modules/workload`).
  - Люди × недели: сумма оценок или число задач (переключатель) по исполнителю и сроку.
  - Ёмкость человека в настройке (часов в неделю); перегрузка подсвечивается.
  - Клик по ячейке — список задач.
- **PT-4 Дашборды** (`modules/dashboards`).
  - Дашборд пространства или личный, сетка виджетов (перетаскивание, размер).
  - Виджеты: число, столбцы по полю, линия во времени (создано или закрыто по неделям), список задач. Каждый — по F-filter.
  - Графики своим SVG, без новой библиотеки.
  - Данные считаются на клиенте по реплике. Шорткат: при реплике > 50 000 задач — серверная агрегация.
- **PT-5 Формы** (`modules/forms`).
  - Форма проекта: поля (название, описание, пользовательские поля, email отправителя); публичная ссылка `/f/<slug>` без входа.
  - Задача создаётся системным пользователем «Форма» в указанном статусе.
  - **Защита публичного эндпоинта:**
    - валидация по схеме формы и лимиты длины;
    - лимит частоты по IP (таблица в Postgres);
    - honeypot-поле;
    - выключенная форма — 404;
    - вложения — по лимиту `/files`.
  - Страница формы — отдельный лёгкий чанк без загрузки приложения.
- **PT-6 GitLab** (`modules/gitlab`, опрос API).
  - Настройки (только админ): URL GitLab, токен доступа (хранится зашифрованным AES-256-GCM, ключ из env `PLANAR_SECRET_KEY`; в ответах API не отдаётся), список проектов GitLab, интервал опроса (по умолчанию 2 мин).
  - Задача pg-boss cron: для каждого проекта `GET /projects/:id/merge_requests?updated_after=<курсор>`, постранично. MR привязывается к задаче, если ключ `PLN-123` есть в названии, ветке или описании.
  - Сущность `gitlabMrs` (задача, проект, iid, название, ветка, состояние, автор, url, обновлено). Курсор на проект.
  - Блок «GitLab» в карточке задачи: MR, их состояние и ссылки. По желанию — авто-статус задачи при merge (настройка проекта: «MR смержен → статус X»).
  - Ошибки GitLab (401, 404, лимит) — в журнал модуля и в настройки, без падения опроса.
  - Приёмка — против фейкового сервера GitLab в тесте: пагинация, курсор, сопоставление ключей, шифрование токена, обработка 401 и 429.
- **PT-7 e2e фазы 3.** По сценарию на каждую функцию в `e2e/web/p3.spec.ts`. Замер §7.

## 5. Волны
- PT-0 ‖ PT-1 ‖ PT-6 ‖ PT-5 (серверная часть) → PT-2 ‖ PT-3 ‖ PT-4 → интерфейс PT-5 и PT-6 → PT-7.
- Интерфейсы новых экранов — после слияния DS-0 (C-ui v3) из `feature/design`: влить его в `feature/p3`.
- Не больше 4 исполнителей.

## 6. Правила среды
- Как в `docs/plan/core.md` §4 и `docs/plan/web.md` §4. Отчёт — только в `build/dpcli/<ID>.report.json` своей копии.
- Слияние — только `.dpcli/dpcli merge <ветка> --into feature/p3`.
- Порт 3000 занят, 3300 и 5173 — стек пользователя. Свои `API_PORT`, `WEB_PORT`, `COMPOSE_PROJECT_NAME`.
- Тестовая БД `planar-testdb` работает без fsync (`dev.sh testdb`). Если контейнер старый — его пересоздаёт главная.
- Файлы `apps/web/src/layout` и `apps/web/src/ui` — зона `design`; `p3` их не правит. Нужна точка расширения — через C-modules (`contract:` главной).
