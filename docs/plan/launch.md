# План запуска Planar: open source + демо + облако/услуги

## Context

Planar — трекер задач уровня ClickUp с local-first синхронизацией как в Linear, MCP и REST, модулями (`modules/*`), prod-стеком на docker compose + Caddy и бэкапами (`ops/`, `docs/guides/deploy.md`). Его выводим в open source (GitHub + GitLab) и зарабатываем на облаке (SaaS), платном внедрении и разработке модулей на заказ.

**Решения пользователя (2026-10-26):** имя **Planar** остаётся; лицензия MIT/Apache-2.0; рынок — оба, основной английский; аналитика — GA + Яндекс Метрика; облачная платформа — **отдельно от продукта**: инстанс на клиента, одна СУБД на всех, свой скрипт на `docker compose`, Cloudflare перед всем, $10/инстанс/мес с 30 днями бесплатно, оплата Paddle + Lemon Squeezy + ЮKassa + CloudPayments; `gh` и `glab` на хосте авторизованы.

**Что видно в репо сейчас:** нет README, LICENSE, CI; `.env` не в git, `.env.example` есть; 1168 коммитов, в истории внутренняя кухня (`docs/plan/` 3,1 МБ журналов, `.dpcli/`, `.claude/`, `e2e/_*.mjs`); около 680 строк комментариев на русском; первый владелец создаётся через `POST /setup` (`apps/api/src/auth/setup.controller.ts`).

## 0. Домены (проверено 2026-10-26 по RDAP; окончательно — у регистратора, часть может быть «премиум» по цене)

**Свободны:**
- planarhq: **.com, .io, .dev, .app, .net, .ru**
- planar.*: **.team, .tools, .run, .software, .build, .works, .page, .chat, .live, .design, .tech, .systems, .inc, .link, .codes, .su**; вероятно свободны (RDAP по этим зонам ненадёжен) .to, .fm, .pm, .ws, .рф, .kz
- **Заняты:** planar.com, .dev, .io, .app, .so, .sh, .org, .ru, .work, .space, .cloud, .pro, .one; getplanar.com/.io, useplanar.com

**Рекомендация:** `planarhq.com` — основной (сайт, docs, demo, облако), `planarhq.ru` — русская версия и защита, `planarhq.io` — защита (будет редирект). По желанию короткий `planar.team` — для красивых адресов облачных инстансов (`acme.planar.team`) или редирект.
Поддомены: `planarhq.com` — сайт, `docs.` — документация, `demo.` — демо, `app.` — личный кабинет облака, `*.planar.team` (или `*.planarhq.com`) — инстансы клиентов.
Риск: рядом open-source трекер Plane (plane.so) — путаницу снимаем позиционированием и марками; подать заявку на товарный знак Planar (РФ/ЕС; WIPO Global Brand Database проверю до покупки). При MIT/Apache марка — единственная защита: форк забирает код, но не имя.

## 1. Подготовка репозитория (неделя 1)

**Лицензия:** рекомендую **Apache-2.0** (а не MIT) — та же свобода, но явная патентная лицензия и оговорка, что марка не передаётся. Вклад по DCO (`Signed-off-by`), CLA не нужен.

**Чистая публичная история.** Текущую историю не публикуем (журналы агентов, внутренние планы, рабочие скрипты). Приватный репо остаётся рабочим; публичный создаётся с одного начального коммита из отфильтрованного дерева, дальше — скрипт экспорта приватный → публичный. Исключения: `docs/plan/`, `docs/research/`, `docs/registry/`, `.dpcli/`, `.claude/`, `CLAUDE.md`, `dpcli.yml`, `e2e/_*.mjs`, `data/`, `build/`. Перед публикацией — `gitleaks` по дереву.

**Файлы в корне:** `README.md` (en) + `README.ru.md` (фраза о продукте, GIF, возможности, установка в 3 команды, ссылки на демо/docs/облако); `LICENSE`; `CONTRIBUTING.md` (dev.sh, тесты, DCO, как писать модуль); `CODE_OF_CONDUCT.md`; `SECURITY.md`; `TRADEMARK.md`; `CHANGELOG.md`; шаблоны issue/PR.

**Сборка и выпуск:** GitHub Actions — lint, vitest, сборка образов; образы `api` и `caddy` в GHCR по тегу; `compose.yml` для пользователей на готовых образах вместо `build:`. SemVer, первый выпуск `v0.9.0` (публичная бета). GitHub — основной (`gh` есть), GitLab — зеркало с тем же README.

**Английский в коде:** ~680 строк русских комментариев перевести механически. `docs/guides/deploy.md` и `mcp.md` перевести и вынести на сайт документации.

**Небольшие доработки продукта для облака** (открытый код, полезны и self-host):
- `SETUP_TOKEN` — `POST /setup` принимает первого владельца только с этим токеном (сейчас `/setup` открыт всем до первого пользователя — на публичном адресе это гонка).
- `DB_POOL_MAX` — размер пула соединений (сейчас `new pg.Pool` в `apps/api/src/db/index.ts` с дефолтом 10; при 100 клиентах на одной СУБД это 1000+ соединений). Для облака — 3–4.
- Всё остальное (оплата, кабинет, лимиты) — в продукте не появляется: тариф плоский, связывать облако с инстансом не нужно.

## 2. Демо-стенд (неделя 1–2)

- **Новый сид для демо — на английском, разнообразный и красивый:** вымышленная компания на 8–12 человек с аватарами; 4–5 пространств (Product, Engineering, Marketing, Design, Support); проекты с реальными по виду задачами, статусами, приоритетами, метками, сроками на ближайшие недели, подзадачами, чек-листами, комментариями и @упоминаниями; активный и завершённый спринты, вехи и цели, учёт времени, дашборд, документы, переписка в чате, повторяющиеся задачи — каждый модуль должен показать себя на первом экране. Даты считаются от «сегодня», чтобы демо не устаревало. Основа — существующий `apps/api/src/db/seed` (`SeedLocale`), новый набор данных рядом.
- Флаг `DEMO_MODE`: плашка «данные сбрасываются каждые N часов», вход в один клик под демо-пользователем, выключены email/push/webhooks, малый `MAX_UPLOAD_MB`.
- Сброс по cron из эталонного дампа (`ops/restore.sh`).

## 3. Сайт и документация (неделя 1–2)

- **Документация:** VitePress (стек Vue) на `docs.planarhq.com`: установка, `.env`, обновление и бэкапы, MCP, REST/OpenAPI (из `apps/api/src/rest/openapi`), разработка модулей (`examples/plugin-hello`, `modules/hello`).
- **Лендинг** en + `/ru` — не входит в репо planar, делается вместе с облачным проектом (§6); из planar берёт материалы §4. Желаемые блоки: GIF «без задержек»; local-first и офлайн; возможности; self-host одной командой; ИИ-агенты через MCP; модули; цены (Self-hosted бесплатно / Cloud / Business: внедрение, перенос из ClickUp/Jira через `modules/import`, модули на заказ, поддержка с SLA); сравнение с ClickUp, Jira, Linear, Plane; форма заявки.
- **Аналитика:** GA4 + Яндекс Метрика на сайте и docs. Для посетителей из ЕС нужен баннер согласия на cookies — одна строка, без него GA в ЕС незаконна. В сам продукт (инстансы клиентов) счётчики не ставим.

## 5. Продвижение и сообщество

- **Последовательность:** тихий запуск (знакомые команды, 1–2 недели) → Хабр + Show HN в одну неделю (HN — вт–чт, утро по США) → Reddit → Product Hunt через 1–2 недели.
- **Каталоги:** alternativeto.net, openalternative.co, selfh.st, awesome-mcp-servers; awesome-selfhosted — когда первому выпуску исполнится 4 месяца (их правило).
- **Площадки:** GitHub Discussions; Telegram-чат (ru); Discord (en).
- Публичный роадмап на самом Planar; метки `good first issue`; каталог модулей сообщества; выпуск с changelog раз в 2–4 недели.

## 6. Облако (SaaS) — вне этого репо

Сайт с ценами, оплата, личный кабинет, админка и управление инстансами — отдельный проект; в planar не ведётся и из этой папки не трогается. Уже решено (для того проекта, не для задач planar): инстанс на клиента при одной общей СУБД; свой скрипт на `docker compose` + Traefik за Cloudflare; $10/инстанс/мес, 30 дней бесплатно; оплата Paddle + Lemon Squeezy + ЮKassa + CloudPayments; свой VPS вместо PaaS (~$0,7 на клиента против $2–5). Расчёт и детали — в отдельном проекте `planar-cloud`.

**Что облаку нужно от planar** (входит в задачи ниже): образы в GHCR с версиями, `SETUP_TOKEN` для `POST /setup`, `DB_POOL_MAX`, рабочие `/health` и `/metrics`.

## 7. Что нужно от пользователя

- Купить домены (§0), DNS — Cloudflare.
- Сервер для docs и demo: 4 vCPU / 8 ГБ / 80 ГБ SSD, SSH-доступ.
- GitHub-организация и GitLab-группа — репо и зеркало создам сам через `gh` и `glab` после «да»; почта на домене (hello@, security@) + SMTP, счётчики GA и Метрики.
- Аккаунты для публикаций (Хабр, Reddit, HN, Product Hunt) — публикует сам пользователь: аккаунты с историей работают лучше.

## 8. Порядок выполнения

Только репо planar. Через `.dpcli/dpcli`: модуль `launch` (`module new launch --from main`, не от `feature/inbox-split`), план `docs/plan/launch.md` в planar, один координатор, задача — один исполнитель.

1. (`dp-mechanic`) перевод комментариев на английский.
2. (`dp-writer`) README en/ru, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, TRADEMARK, CHANGELOG, LICENSE.
3. (`dp-engineer`) CI, образы в GHCR, compose на готовых образах, скрипт экспорта в публичный репо.
4. (`dp-engineer`) `SETUP_TOKEN`, `DB_POOL_MAX`, `DEMO_MODE`.
5. (`dp-engineer`) английский демо-сид + cron-сброс демо.
6. (`dp-writer`) сайт документации (VitePress).
7. (`dp-writer`) материалы: статья для Хабра + английская версия, тексты постов, one-pager.

Задачи 1–3 последовательно (одни файлы), 4–7 — параллельно по 2–3. Без масштабирования агентов сверх этого; перед запуском назову оценку токенов и дождусь «да».

## Проверка

- Чистая VM: клон публичного репо → `cp .env.example .env` → `docker compose up -d` → вход и создание задачи ≤5 мин.
- `gitleaks detect` по публичному дереву — пусто; нет `docs/plan`, `.dpcli`, `.claude`.
- CI зелёный; образы из GHCR скачиваются без авторизации.
- `/setup` без `SETUP_TOKEN` (когда он задан) отвечает отказом; `DB_POOL_MAX` ограничивает пул; тесты на оба.
- Демо: каждый модуль заполнен на первом экране, даты относительно сегодня; сброс по cron восстанавливает эталон.
- `pnpm test` и e2e проходят после перевода комментариев и новых флагов.
- Docs: Lighthouse ≥90, проверка ссылок, en/ru, счётчики приходят.
