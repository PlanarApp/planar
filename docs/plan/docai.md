# Модуль docai — ИИ в комментариях к документам

## 1. Цель
PLNRAPP-219, шаг 2 разбивки PLNRAPP-209. Комментарии к страницам (`docs_comments`, мутаторы `docs.comment.*`, `modules/docs/web/DocComments.vue`, уведомления `doc_mention` / `doc_comment_assigned`) уже есть (MR !201). Нужно, чтобы ИИ работал в них так же, как в комментариях задачи:
- `@ai` или ответ на комментарий ИИ — ИИ отвечает в ветке комментария страницы;
- комментарий, назначенный на ИИ, — ИИ выполняет поручение, в том числе правит страницу, и закрывает комментарий;
- события `comment` и `mention` документа идут через инструкции harness-пакета (PLNRAPP-198), с runtime agent, если он выбран;
- индикатор работы ИИ в комментариях документа (как PLNRAPP-202 в задаче);
- бот ИИ возвращается в список назначения (`DocComments.vue` сейчас фильтрует bot);
- «Адаптировать с помощью ИИ» в мастере — через поручение ИИ с патчем; `api/ai/wizard/adapt` (`modules/ai/api/wizard-adapt.controller.ts`) удалить вместе с переводами и тестами.

## 2. Решения пользователя (ответы в PLNRAPP-209, 2026-11-13)
- Своя таблица `docs_comments` в модуле docs (сделано на шаге 1).
- Уведомления расширены на страницы (сделано на шаге 1).
- `ai_runs`: новое поле `page_id`, `task_id` может быть пустым. Контекст прогона для страницы: текст страницы, ветка комментария, для страниц harness-пакета — статусы и правила проекта. Ответ — `docs.comment.create` в ветку; поручение — правка и `docs.comment.resolve`.
- Runtime agent для документов — да, уже в этом шаге. Для этого нужны инструменты MCP для комментариев страницы и патча страницы, по правилу паритета REST ↔ MCP (`apps/api/src/rest`, `apps/api/src/mcp/tools.ts`, строка `PARITY` в `apps/api/test/mcp/mcp.test.ts`, тест).
- Правка документа ИИ — патч «найти → заменить» по markdown-тексту страницы, применяется на сервере через `docs.page.update`: правка попадает в историю версий, а в открытом редакторе появляется через collab (`CollabService.external`). Страницы с упоминаниями отклоняются (markdown их ломает).
- Комментарии к выделенному фрагменту — шаг 3, вне этого модуля.

## 3. Задачи
Разбивку на задачи, карточки и волны делает координатор по коду (`modules/ai/api/run.ts`, `modules/ai/api/*`, `modules/docs/*`, `apps/api/src/mcp`, `apps/api/src/rest`, `modules/ai/harnesses/*`). Ориентир:
- данные и конвейер: миграция `ai_runs.page_id`, обобщение `run.ts` на страницу (контекст, ответ, resolve, перезапуск), триггеры событий `docs.comment.*` (упоминание `@ai`, ответ на ИИ, назначение на ИИ);
- патч страницы: формат, применение через `docs.page.update`, отказ на страницах с упоминаниями; REST + MCP-инструменты комментариев страницы и патча;
- runtime agent и инструкции harness-пакета для событий документа;
- web: бот в назначении, индикатор работы ИИ в `DocComments.vue`; мастер «Адаптировать» через поручение, удаление `api/ai/wizard/adapt`;
- контракты (`docs/contracts/*`), CHANGELOG, демо-сид `apps/api/src/db/seed-demo.ts` (ветка с ответом ИИ и закрытым поручением на странице), документация `docs-site/` про ИИ в документах.

## 4. Доставка
Полный `pnpm test` и `pnpm -s lint`; перед deliver — `git fetch origin main`, если main ушёл вперёд — обновить `mr/PLNRAPP-219` и `.dpcli/dpcli sync docai`; `.dpcli/dpcli deliver docai --into mr/PLNRAPP-219`; `docai done`. Пуш и MR делает главная сессия.

## 5. Условия остановки
- Нужна правка ядра вне `ai_runs` и паритета REST/MCP (схема `comments` задач, sync-протокол) — вопрос пользователю.
- Патч по markdown не может сохранить нужную разметку страницы, кроме упоминаний, — вопрос пользователю.
