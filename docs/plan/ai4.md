# Модуль ai4 (AIH)

## 1. Цель
PLNRAPP-169: harness хранится в документах проекта (`Harness-пакеты/[Пакет]/[Инструкция]`), структурные изменения применяются кнопкой «Применить harness» (parse → zod → diff → подтверждение → пачка мутаций), пакет можно загрузить из каталога/zip и экспортировать, в каталоге есть пакет «Разработка» (только llm-действия). Источник: `build/ai-plan.md` §6, «Решения», «Что переиспользуем». Не входит: agent-действия (ИИ-11), визард, «ИИ-диалог по документу» (ИИ-5).

## 2. Решения
- Формат — как в `build/ai-plan.md` §6: `harness.yml` (statuses, labels, fields, actions, rules, settings) + `actions/*.md` (frontmatter `name, description, runtime, model, checks`; тело — промпт). Документ инструкции в проекте: 1-й абзац — описание, таблица параметров, далее промпт.
- Вся схема БД (`ai_harness_keys`, `ai_harness_packs`) и миграция 0052 — в AIH-1, чтобы параллельные задачи волны 2 не конфликтовали по миграциям.
- Harness-эндпоинты — Nest-контроллер модуля ai для UI настроек (admin проекта), не REST v1: агенты работают с документами через существующие docs-инструменты MCP; паритет не затрагивается. Если исполнитель тронет REST v1 — MCP и строка PARITY обязательны.
- Apply — одна пачка мутаций через `executeMutations` с origin системы; правила создаются с `enabled=false`, в конце включаются.
- Ревьюер — только для AIH-2 (apply мутирует статусы с `replaceWith`).

## 3. Задачи
- **AIH-1** (волна 1). Формат и ядро: `modules/ai/shared/harness.ts` — zod-схема harness.yml и параметров инструкции, разбор md/yaml, `diff(текущее состояние проекта, пакет)` → действия create/update/delete, валидация `replaceWith`, порядок применения; таблицы `ai_harness_keys (projectId, kind, key → entityId)` и `ai_harness_packs` (projectId, packKey, active, rootPageId, hashes jsonb) + миграция 0052. Тесты: zod, diff, replaceWith, порядок.
- **AIH-2** (волна 2, зависит от AIH-1). API: контроллер `POST /ai/harness/diff` и `/apply` (admin проекта): чтение блока harness.yml из документа пакета, применение пачкой в порядке статусы → метки → поля → действия (`ai_actions.pageId` = страница инструкции) → правила (`enabled=false`, затем включение), запись ключей, цвет и rank по умолчанию. Промпт читается из страницы инструкции в момент прогона (подмена встроенного «Поручения» из `run.ts`). Ревью.
- **AIH-3** (волна 2, зависит от AIH-1). Пакет «Разработка» в `modules/ai/harnesses/dev/` (Планирование с оценкой поля «Бюджет», Декомпозиция, Триаж, Сводка обсуждения, Поручение, Чат; только llm); загрузка каталога/zip в документы проекта с хешами страниц, выбор активного пакета, сброс/«оставить мои»/«объединить» (ИИ-слияние), экспорт zip, сброс активного при удалении документов; демо-сид `apps/api/src/db/seed-demo.ts`.
- **AIH-4** (волна 3, зависит от AIH-2, AIH-3). Web: кнопка «Применить harness» в панели документа пакета (diff, выбор `replaceWith`, подтверждение), раздел «Пакеты» в настройках ИИ (загрузить, активный, повторная загрузка, экспорт), i18n.

## 4. Волны
1: AIH-1. 2: AIH-2 + AIH-3. 3: AIH-4. Один координатор — одна волна.

## 5. Условия остановки
Конфликт с контрактами docs/automations; apply требует изменения мутаторов ядра.
