# Модуль design (DS)

## 1. Цель
Сделать интерфейс Planar цельным, плотным и строгим, как в Linear. Функции не меняются. Бюджеты `docs/roadmap.md` §7 не ухудшаются, начальный JS ≤ 200 КБ.

## 2. Решения пользователя
- Визуал «плотно и строго, как Linear» (2026-10-24).
- Простота: вторичное — в меню, по наведению и в Cmd+K.
- В `main` — только с одобрения пользователя.

## 3. Аудит (главная, скриншоты 1440×900 и 390×844 на main 6ed3d99)
1. **Боковая панель.**
   - Секции модулей (Чат, Документы, Мои часы, Импорт) вклинены между ядром и пространствами.
   - Размеры шрифтов скачут от 11 до 14 px.
   - Нет шапки workspace.
   - В «Чат» показаны имена пространств вместо каналов.
   - Пустое «Избранное» занимает место.
2. **Верхняя панель.** Вместо хлебных крошек — общее слово «Проект». Иконка чата дублирует боковую панель.
3. **Панель проекта.** Восемь кнопок одного веса (Статус, Вручную, сортировка, Подзадачи, Фильтр, Поля, Сохранить как вид). На mobile — 4 строки, треть экрана.
4. **Список.**
   - В каждой строке «—» и иконка календаря у пустых полей — шум.
   - Нет аватаров исполнителей.
   - Метки — только иконкой.
5. **Доска.** Карточки высокие и полупустые.
6. **Пустые состояния.** Например, в чате — голый текст в левом верхнем углу без отступов.
7. **Настройки.** Сплошные красные «Удалить» у каждой строки.
8. **Данные сида.** Статусы на английском (Backlog/Todo) в русском интерфейсе.

## 4. Контракт C-ui v3 (координатор пишет до DS-1, `docs/contracts/web.md` §C-ui)
- **Токены.** Нейтральная шкала из 10 ступеней, один акцент, семантические цвета (danger, warning, success); тёмная боковая панель в обеих темах; радиусы 4/6/8; тени только у всплывающих элементов.
- **Типографика.** База 13 px; шкала 11/12/13/14/16/20; моноширинный шрифт для ID; межстрочный интервал.
- **Плотность.** Строка списка 32 px, элемент боковой панели 28 px, кнопки 28/32 px, шаг сетки 4 px.
- **Компоненты.** Button (primary, secondary, ghost, danger-ghost), IconButton, Input, Select, Menu, Popover, Dialog с подтверждением деструктивного действия, Tabs, Chip, Avatar и AvatarStack, Badge, Kbd, EmptyState, Toolbar, Tooltip. Всё на Reka UI.
- **Правила.**
  - Деструктивные действия — в меню «…» с подтверждением, а не сплошной красной кнопкой.
  - Пустые значения в строках не показываются.
  - Вторичные действия — по наведению.
- Потребители: web, все `modules/*/web`, модуль `p3`. Токены и компоненты доступны модулям через SDK (`@planar/web/modules`). Если добавление в SDK меняет C-modules — строкой `contract:` главной.

## 5. Задачи
- **DS-0 Контракт C-ui v3, токены и базовые компоненты.**
  - Состав: CSS-переменные, Tailwind-тема, компоненты из §4, страница-витрина `/dev/ui` (только в dev).
  - Приёмка: контрактный тест (перечень токенов и компонентов), контраст текста ≥ 4.5:1 (axe или своя проверка), начальный JS ≤ 200 КБ.
  - Первая задача: от неё зависят DS-1…DS-5 и модуль `p3`.
- **DS-1 Оболочка.**
  - Боковая панель:
    - шапка workspace (название и меню пользователя);
    - Inbox и «Мои задачи»;
    - «Избранное» (скрыто, если пусто);
    - пространства: сворачиваются, внутри проекты;
    - группа «Разделы» с секциями модулей: каналы чата со счётчиками, дерево документов, часы, импорт;
    - всё сворачивается, состояние сохраняется.
  - Верхняя панель — хлебные крошки «пространство / проект / вид», поиск (Cmd+K), колокольчик. Иконку чата убрать.
- **DS-2 Панель проекта.**
  - Вкладки видов.
  - Одна кнопка «Вид» (popover: группировка, сортировка, подзадачи, поля).
  - «Фильтр» с чипами активных фильтров.
  - «Сохранить вид» — в меню «…».
  - На mobile — одна строка с горизонтальной прокруткой.
- **DS-3 Список и Доска.**
  - Строка: ID моноширинным шрифтом, иконка статуса, название; справа — только заданные метки (точка с названием), срок (если есть), аватары исполнителей; действия по наведению.
  - Карточка доски: компактная — ID, название, нижняя строка с метками, сроком и аватарами.
  - Сид: статусы на русском при `ru`.
  - Не ухудшать скорость прокрутки и переключения (замер §7).
- **DS-4 Карточка задачи, настройки, диалоги, пустые состояния.**
  - Карточка: свойства справа колонкой «ключ — значение»; заголовок и описание крупнее.
  - Настройки: единый шаблон «список + меню “…”», удаление с подтверждением.
  - EmptyState во всех пустых экранах: чат, документы, Inbox, «Мои задачи», поиск.
  - Модули chat, docs, time, sprints, automations, webhooks, import — переход на компоненты C-ui v3 (замена своих кнопок и полей).
- **DS-5 Mobile и скриншотные тесты.**
  - Проход по mobile: нижняя навигация, полноэкранная карточка задачи, листы (sheets) вместо popover.
  - `e2e/web/visual.spec.ts`: Playwright `toHaveScreenshot` на 12 экранов × 2 ширины × 2 темы, эталоны в репозитории.
  - Финальный замер §7.

## 6. Волны
DS-0 → DS-1 ‖ DS-2 ‖ DS-3 → DS-4 ‖ DS-5. Не больше 4 исполнителей.

## 7. Правила среды
- Как в `docs/plan/web.md` §4. Отчёт исполнителя — только в `build/dpcli/<ID>.report.json` своей копии.
- Слияние ветки задачи — только `.dpcli/dpcli merge <ветка> --into feature/design`.
- На хосте порт 3000 занят. Стеки поднимать со своими `API_PORT`, `WEB_PORT` и `COMPOSE_PROJECT_NAME`. Порты 3300 и 5173 занимает стек проверки пользователя.
- Визуальную проверку делает исполнитель сам: скриншоты Playwright в `build/artifacts/<ID>/`, до и после. Мелкие визуальные правки — не больше 2 попыток.
- Параллельно идёт модуль `p3` (в основном в `modules/*` и серверной части). Общие файлы `apps/web/src/layout`, `apps/web/src/ui` правит только `design`.
