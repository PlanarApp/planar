# Контракты модуля p3

Владелец — координатор p3. Формат сущностей и мутаторов — как в `docs/contracts/core.md` (C-schema «Общие правила», «Типы», «Видимость и права») и `core-mutators.md`. Модули — по C-modules (`modules/<id>`, пакет `@planar/module-<id>`, таблицы `<id>_<snake>`, маршруты `/api/<id>/`).

Контрактный тест — `apps/api/test/modules/p3.contract.test.ts`: сверяет разделы `#### <сущность>` и таблицы мутаторов этого файла с `shared.entities` и `shared.mutators` модулей. Модуль, которого ещё нет в `installed.ts`, пропускается; `P3_CONTRACT_STRICT=1` — отсутствие модуля = ошибка (проверка в карточке задачи модуля).

Правки C-* (ядро) в этом файле не делаются: одобрены главной (C-schema v9 — `ydocs`; C-http v11 — WS `/collab`, env `PLANAR_SECRET_KEY`, вход `/f/*`; C-modules v9 — `CoreServices.execute`, `ensureSystemUser`, `storeFile`) и вносятся в `core.md` задачей p3. Ниже они помечены «→ C-…».

## P3-collab v1 (PT-1)

### Протокол
- Hocuspocus (`@hocuspocus/server`) в процессе api, WebSocket на пути `/collab` того же HTTP-сервера, что `/ws` (→ C-http: путь `/collab`; Vite dev и Caddy проксируют его как `/ws`).
- Имя документа: `docs:<pageId>` (страница `docsPages`) или `task:<taskId>` (описание задачи). Другое имя — отказ.
- Поле Yjs: `Y.XmlFragment` с именем `default` (по умолчанию у `@tiptap/extension-collaboration`).
- Шорткат: один процесс api; несколько процессов — `@hocuspocus/extension-redis`.

### Авторизация
- Upgrade `/collab`: cookie `planar_sid` — действующая сессия, активный пользователь; `Origin` = origin `PUBLIC_URL` (как `/ws`, C-http «Сессия и Origin»). Иначе upgrade отклоняется (401/403), до Hocuspocus. Bearer не принимается.
- `onAuthenticate` на каждый документ:
  - `docs:<id>` — модуль docs включён, страница есть, пользователь — участник её пространства. Роль ≥ member — запись; guest или архивная страница — `connection.readOnly = true`.
  - `task:<id>` — задача есть, пользователь — участник её пространства. Роль ≥ member — запись, guest — только чтение.
  - Иначе — отказ (`forbidden` или `not_found`), документ не загружается.
- Пользователя удалили из пространства (`spaceMembers` del) или деактивировали — его соединения с документами этого пространства закрываются.
- Awareness: `user: {id, name, color}`. `color` — детерминирован по `userId`: индекс `hash(userId) mod N` в общей палитре курсоров (один источник для всех клиентов). Шорткат: сервер awareness не проверяет.

## P3-ydoc v1 (PT-1)

### Хранение
Несинхронизируемая таблица ядра (→ C-schema, «Несинхронизируемые таблицы»):

| таблица | колонки |
|---|---|
| `ydocs` | `doc_id text pk` (имя документа, `docs:<uuid>` \| `task:<uuid>`), `state bytea not null` (`Y.encodeStateAsUpdate`), `updated_at timestamptz` |

Схема — `apps/api/src/db/schema.ts`, миграция drizzle-kit.

### Загрузка (`onLoadDocument`)
- Строка `ydocs` есть — применить `state`.
- Нет — Y.Doc из текущего JSON: `docsPages.body` или `tasks.description` (`null` → пустой `doc`), через схему ProseMirror редактора. Это и есть миграция существующих тел: отдельного прогона нет.
- Схема ProseMirror — **один** список расширений TipTap для web и api, без DOM и Vue (node views подключает только web). Своей копии схемы на сервере нет.

### Сохранение и проекция (`onStoreDocument`)
- Debounce 2 с после последней правки, не реже раза в 10 с при непрерывной правке; при закрытии последнего соединения — сразу.
- Порядок: записать `ydocs.state` → собрать JSON из `default` (`yXmlFragmentToProsemirrorJSON` или `TiptapTransformer.fromYdoc`) → если JSON не равен текущему полю (глубокое сравнение) — мутатор от имени **последнего правившего** пользователя, обычные права (не `system`):
  - `docs:<id>` → `docs.page.update {id, body}` (мутатор сам считает `text`, `files`, `updatedBy`);
  - `task:<id>` → `task.update {id, description}`.
- Так синхронизация, поиск, REST v1, MCP, activity работают как раньше. C-sync и C-mutators не меняются.
- Мутатор отклонил (права, `conflict` у архивной страницы, `invalid_args` при > 512 КБ) — `log.warn`, `ydocs` уже сохранён, следующее сохранение пробует снова.

### Внешняя запись
- Внешняя запись — смена `docsPages.body` или `tasks.description` не проекцией: REST v1, MCP, мутатор офлайн-клиента старой версии, `task.create` с описанием.
- Правило без меток: если новый JSON глубоко равен проекции текущего Y.Doc — ничего (так проекция не зацикливается). Иначе:
  - документ загружен в Hocuspocus — содержимое `default` заменяется новым JSON одной Y-транзакцией, клиенты получают замену (последняя запись побеждает);
  - не загружен — строка `ydocs` удаляется, следующее открытие строит Y.Doc из JSON.
- Удаление задачи (`task.delete`) — удалить `ydocs` `task:<id>`, закрыть соединения документа.

### Клиент (web)
- `Editor.vue` (`apps/web/src/task/editor/`) — необязательный проп `collab?: { name: string }`. Задан → расширения Collaboration и курсоры (`@tiptap/extension-collaboration`, `collaboration-cursor`/`collaboration-caret` по версии TipTap), `HocuspocusProvider` на `/collab` того же origin (`ws:`/`wss:`), `y-indexeddb` с ключом `name`; встроенная история TipTap выключена (undo — Yjs). Не задан — как раньше.
- Документ docs и описание задачи открываются с `collab`; редактор комментариев — без.
- Офлайн: правки копятся в IndexedDB, после переподключения догоняются через Yjs. Тело страницы и описание задачи редактором больше не пишутся через мутатор (`title`, `icon` — по-прежнему `docs.page.update`).
- `readOnly` соединения → `editable = false`.
- **DC-web v2 (вместо мягкой блокировки CL-3):** web не вызывает `docs.lock`/`docs.unlock`, не показывает «редактирует X» и режим чтения. Сущность `docsLocks` и мутаторы `docs.lock`/`docs.unlock` остаются (DC-schema, DC-mutators v1 без изменений), их тесты зелёные. Удаление — отдельной задачей по запросу.

## P3-timeline v1 (PT-2)
Модуль `timeline`, синхронизируемых сущностей и мутаторов нет.
- Web: `views` — `{id: 'timeline', label: {ru: 'Таймлайн', en: 'Timeline'}}`, экран проекта `/p/:projectId/timeline:timeline` (ключ вкладки модуля — `<moduleId>:<viewId>`, C-views). Задачи — `useProjectTasks` (C-tasks), связи — `taskLinks` (F-links).
- Полоса задачи: даты включительно. Есть `startDate` и `dueDate` — `[startDate, dueDate]`; только одна из дат — 1 день на ней; `startDate > dueDate` — рисуется `[dueDate, startDate]`. Обеих нет — колонка «Без дат», оттуда перетаскиванием на шкалу (ставит обе даты, длительность 1 день).
- Перенос полосы — `task.update {id, startDate, dueDate}` со сдвигом обеих дат; растягивание края — меняет одну дату. Задача с одной датой при растягивании получает обе.
- Масштаб: день, неделя, месяц; начало недели — `useWeekStart()`.
- Зависимости: стрелка от конца A к началу B для каждой строки `taskLinks {taskId: A, targetId: B, kind: 'blocks'}`, обе задачи на шкале. Нарушение — начало B ≤ конец A. После переноса, создавшего нарушение, — предупреждение (toast), стрелка подсвечена; даты не сдвигаются.
- Виртуализация: рисуются только видимые строки (± запас) и видимый диапазон дат. Приёмка: 10 000 задач, 2 с прокрутки — нет long task > 50 мс (`PerformanceObserver` `longtask`).

| `id` | uuid | уникально (spaceId, userId) |

| `hoursPerWeek` | int | 0–168 |
| `updatedBy` | uuid | |

| мутатор | args | правила |
|---|---|---|
| `workload.setCapacity` | `id, spaceId, userId, hoursPerWeek: int\|null` | `null` — удалить строку; `userId` не участник пространства → `invalid_args`; уже есть строка (spaceId, userId) с другим `id` → обновляется она; `updatedBy = ctx.userId` |

- Нет строки — ёмкость 40 ч/нед.
- Web: `nav` `workload:page` → `/m/workload` (выбор пространства). Таблица: строки — участники пространства, столбцы — недели (`useWeekStart()`, 8 недель от текущей, листается).
- Учитываются задачи пространства с исполнителями, категория статуса не `done`/`cancelled`, есть `dueDate`.
- Режим «оценки» (только при включённом модуле time): часы = `timeEstimates.minutes / 60`, делятся поровну между исполнителями. Есть и `startDate`, и `dueDate` — часы делятся поровну по дням `[startDate, dueDate]` и суммируются по неделям; иначе — вся оценка в неделю `dueDate`. Задача без оценки — 0 ч.
- Режим «число задач»: задача считается 1 раз у каждого исполнителя в неделе `dueDate`.
- Перегрузка: часы недели > ёмкости (режим «оценки») — ячейка подсвечена токеном ошибки C-ui. Клик по ячейке — список задач ячейки (`openTask`).

### Публичный эндпоинт (без входа)
| метод и путь | вход → выход |
|---|---|
| `GET /api/forms/public/:slug` | → `{title, description, fields: [{key, label, required, type, options?}]}`; `type` — `text`, `longtext` (description), `email` или тип поля F-fields; `options` — варианты `select` |
| `POST /api/forms/public/:slug` | `{values: {<key>: значение}, website: string}` → `201 {ok: true}` |

- Нет формы, `enabled = false`, проект архивный, модуль выключен — `404` (`not_found` / `module_disabled`); тело не раскрывает, какое из условий.
- Валидация по схеме формы (zod, собирается из `fields`): обязательные поля, лимиты — `title` 1–500, `description` ≤ 10 000, `email` — e-mail ≤ 254, `field:` — по F-fields; лишние ключи → `400 invalid_request`. Тело JSON ≤ 64 КБ → иначе `413`.
- Honeypot: `website` не пустой → `201 {ok: true}`, задача не создаётся.
- Лимит частоты по IP (тот же источник IP, что у лимита входа): ≤ 5 отправок в минуту и ≤ 30 в час на IP по всем формам → `429 rate_limited`. Таблица `forms_rate_limits(key text pk, count int, window_started_at timestamptz)` — ключ `<ip>|m` и `<ip>|h`. Считаются все запросы POST, кроме отклонённых 404.
- Задача: `task.create` через `CoreServices.execute` (C-modules v9) от системного пользователя «Форма» (`CoreServices.ensureSystemUser('form', 'Форма')`: деактивирован, без пароля, как «Автоматизация»), одной транзакцией с `task.setField` и `attachment.create`, `statusId` формы, `rank` — в конец, `description` — текст как абзацы + последний абзац «Отправитель: <email>», если email задан.
- Вложения: форма с `allowFiles: true` в схеме (`FormField` с `key: 'files'`) принимает `multipart/form-data`: поле `payload` — JSON `{values, website}` как выше, поля `file` — до 3 файлов, сумма ≤ `MAX_UPLOAD_MB` (→ `413`). Файлы — `CoreServices.storeFile` (C-modules v9) от пользователя «Форма», затем `attachment.create` на задачу. Без `files` в схеме multipart → `400`.
- Страница `/f/<slug>`: отдельный вход Vite (свой HTML, не грузит приложение), → C-http: путь `/f/*` в dev и Caddy. Размер — ≤ 30 КБ gzip. Без входа; ошибки 404/429/400 — понятным текстом.
- Web приложения: `settings` `forms:forms` — список форм проекта, конструктор полей, ссылка, включение.

## P3-gitlab v1 (PT-6)
Модуль `gitlab`. Сервер сам опрашивает GitLab REST API v4; без вебхуков и без `glab`.

### Серверные таблицы (не синхронизируются)
- `gitlab_config` (одна строка, `id text pk = 'default'`): `base_url text`, `token_enc text?`, `interval_sec int` (60–3600, по умолчанию 120), `last_error text?`, `last_error_at timestamptz?`, `updated_at`.
- `gitlab_projects`: `id uuid pk`, `gitlab_project_id int unique`, `path text` (`group/name`, для показа), `cursor timestamptz?` (наибольший `updated_at` обработанных MR), `last_polled_at timestamptz?`, `last_error text?`, `last_error_at timestamptz?`, `created_at`.

### Токен
- AES-256-GCM, ключ — env `PLANAR_SECRET_KEY` (32 байта в base64; → C-http, окружение api). `token_enc = 'v1:' + base64(iv 12 байт) + ':' + base64(tag 16 байт) + ':' + base64(шифротекст)`; iv — случайный на каждую запись.
- Ключ не задан или неверной длины — сохранение токена `503 unavailable`, опрос не идёт (ошибка в `last_error`).
- Токен не отдаётся ни в одном ответе и не пишется в лог; ответ — `hasToken: boolean`.

### REST (только `users.role` ∈ {owner, admin}, иначе 403; Bearer → 403 — как webhooks)
| метод и путь | вход → выход |
|---|---|
| `GET /api/gitlab/config` | → `{baseUrl, hasToken, intervalSec, lastError, lastErrorAt, projects: [{id, gitlabProjectId, path, lastPolledAt, lastError, lastErrorAt}]}` |
| `PUT /api/gitlab/config` | `{baseUrl?, token?: string\|null, intervalSec?}` → как GET; `baseUrl` — `http:`/`https:` без userinfo; `token: null` — удалить |
| `POST /api/gitlab/projects` | `{project: string}` (числовой id или путь `group/name`) → `201 {project}`; id ищется `GET /projects/:id` |
| `DELETE /api/gitlab/projects/:id` | → `204`; его строки `gitlabMrs` удаляются |
| `POST /api/gitlab/poll` | → `202` — внеочередной опрос |

### Опрос
- pg-boss: `gitlab.tick` (cron `* * * * *`) ставит `gitlab.poll` (singletonKey `gitlab.poll`), если с последнего опроса прошло ≥ `interval_sec`.
- На проект: `GET {base}/api/v4/projects/:id/merge_requests?updated_after=<cursor>&order_by=updated_at&sort=asc&per_page=100&page=N`, заголовок `PRIVATE-TOKEN`; страницы по `X-Next-Page` до пустого. Курсора нет — `updated_after` = сейчас − 30 дней. `updated_after` запроса фиксируется до обхода страниц; продвинутый курсор сохраняется отдельно.
- Курсор двигается после каждой обработанной страницы. `updated_after` включителен: MR с `updated_at = cursor` обрабатывается повторно (upsert идемпотентен).
- Ключ задачи: `\b([A-Z][A-Z0-9]{1,9})-(\d+)\b` в `title`, `source_branch` (регистр не важен) и `description`; ищется задача проекта с таким `key` и `number`. Нет задачи — ключ пропускается.
- Ошибки: 401/403 — `last_error` в `gitlab_config` (`unauthorized`), опрос останавливается до смены токена; 404 проекта — `last_error` проекта, остальные проекты идут; 429 — ждать `Retry-After` (≤ 300 с) один раз, иначе отложить проект до следующего тика; 5xx/сеть — `last_error`, следующий тик. Опрос не падает; каждая ошибка — `log.warn` без токена.
