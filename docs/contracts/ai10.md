# Контракт ai10 — v2

Владелец — координатор ai10. Потребители: RUN-1 (runner), RUN-2 (api), RUN-3 (образ).

## 1. api → ai-runner (внутренняя сеть `runner`)
Заголовок `Authorization: Bearer $AI_RUNNER_TOKEN` (сравнение constant-time), иначе 401. Тело JSON ≤ 2 МБ.
- `POST /v1/runs` `{runId: uuid, image: string, env: {string:string}, limits?: {cpus?: number, memoryMb?: number, pids?: number}, context?: string}` → `201 {containerId}`. Образ не из allowlist (`AI_RUNNER_IMAGES`, через запятую, точное совпадение) → `403 {error:'image_not_allowed'}`; неверное тело → `400`; уже есть контейнер с меткой этого runId → `409`. Потолки limits: `AI_RUNNER_MAX_CPUS` (2), `AI_RUNNER_MAX_MEMORY_MB` (4096), `AI_RUNNER_MAX_PIDS` (512); значения выше — `400`; по умолчанию 1 CPU, 2048 МБ, 256 pids. Имена env — `^[A-Z][A-Z0-9_]*$`, ≤ 64 переменных, значение ≤ 16 КБ. `context` ≤ 1 МБ.
- `GET /v1/runs/:runId` → `200 {state: 'running'|'exited', exitCode?: number}` или `404`.
- `DELETE /v1/runs/:runId` → `204` (идемпотентно; force-remove).
- `GET /healthz` → 200 без токена.

HostConfig фиксированный (клиент его не задаёт): без Binds/Privileged/PidMode; `CapDrop ALL`, `SecurityOpt no-new-privileges`, `ReadonlyRootfs` с tmpfs `/tmp` (256 МБ) и `/work` (размер `AI_RUNNER_TMPFS_MB`, по умолчанию 256, потолок 2048), `Mounts: [{Type:'volume', Target:'/context'}]` (анонимный volume — доступен для записи под ReadonlyRootfs), `AutoRemove: true` (контейнер и volume удаляются при выходе), `NetworkMode = AI_RUNNER_AGENT_NETWORK` (по умолчанию `planar_agents`), `RestartPolicy no`, лимиты Memory/NanoCpus/PidsLimit. Метка `planar.ai.run=<runId>`; имя `planar-ai-run-<runId>`. Контекст — `/context/context.json`: putArchive в `/context` (одна tar-запись `context.json`) в volume `/context`; putArchive в `/` под ReadonlyRootfs docker отклонял (403) (v2).

## 2. Протокол агент-образа (api → контейнер, env)
`PLANAR_RUN_ID`, `PLANAR_RUN_SECRET` (одноразовый секрет прогона), `PLANAR_API_URL` (`http://api:3000`), `PLANAR_LLM_URL` (`$PLANAR_API_URL/api/ai/llm/$PLANAR_RUN_ID`; `x-api-key: $PLANAR_RUN_SECRET`), `PLANAR_RESULT_URL` (`$PLANAR_API_URL/api/ai/runs/$PLANAR_RUN_ID`), `PLANAR_HEARTBEAT_URL` (`…/heartbeat`), `PLANAR_CONTEXT_FILE=/context/context.json`, `HTTP_PROXY`/`HTTPS_PROXY` (squid), `NO_PROXY=api`. Ключа провайдера нет.

Выход: `POST $PLANAR_RESULT_URL` с `Authorization: Bearer $PLANAR_RUN_SECRET`, тело — результат прогона `{verdict: 'done'|'question'|'fail', comment, descriptionAppend?, questions?, newTasks?, moveTo?, labels?, fields?, snoozeUntil?, emails?, docs?, escalate?}` (как у llm-действия); `200` — принято, повтор после принятия — `409`. Heartbeat — `POST $PLANAR_HEARTBEAT_URL` с тем же заголовком каждые 30 с. Выход контейнера без отправленного результата — «жнец» помечает прогон `failed`.

Файл контекста: `{runId, task: {id, key, title, description, status, comments[]}, action: {key, name, prompt}, checks}`.

Закрытые снаружи эндпоинты (Caddy, `deploy/Caddyfile`): `POST /api/ai/llm/*`, `POST /api/ai/runs/:id`, `POST /api/ai/runs/:id/heartbeat` → `404` на внешнем входе; контейнер ходит на `api:3000` по внутренней сети. `runs/:id/stop`, `restart` не затронуты. Контейнер удаляется: `AutoRemove`, `stopAgent` (по `agent_secret_hash is not null`) при результате, ошибке apply, ошибке старта и «Стоп»/жнеце во время старта.

## 3. LLM-прокси (api)
`ANY /api/ai/llm/:runId/*` — без cookie-сессии; секрет прогона в `x-api-key` или `Authorization: Bearer`; sha256 сверяется с `ai_runs.agent_secret_hash`, прогон должен быть `running` и agent. api подставляет ключ подключения проекта и пересылает на `baseUrl` провайдера (только `/v1/messages`, `/v1/chat/completions`; остальное 404), стримит ответ, считает токены (`usage`) в `ai_runs`, проверяет лимиты (`blocked`/`overBudget` из run.ts) до пересылки — превышение `429`. Тело ≤ 1 МБ (глобальный bodyLimit api). Ключ в ответе, логах, ошибках не появляется.

## 4. Результат / heartbeat
`POST /api/ai/runs/:id`, `POST /api/ai/runs/:id/heartbeat` — только секрет прогона (не сессия); неверный секрет — `401`, прогон не `running` — `409`. Результат валидируется той же zod-схемой, что у llm, и применяется тем же `apply`.
