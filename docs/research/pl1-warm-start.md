# PL-1 — разбор тёплого старта с модулями docs,chat

Вывод: на текущей машине тёплый старт ≈ 420 мс **с модулями и без них**; модули на критическом пути не стоят ничего измеримого. 400 мс достигается только ядром (вне скоупа).

## Что нашли на критическом пути с модулями (CPU-профиль + таймлайн stages.spec, warm)
- После чтения `settings.enabled_modules` (~95 мс) грузятся чанки модулей (docs Editor 411 КБ, Section/TreeSection/Topbar) и монтируются секции nav: ещё ~20 транзакций IDB (chatChannels, chatMembers, chatReads, docsPages, users, spaces…) в окне 215–225 мс, пока читаются задачи; первая строка — на 390–410 мс.
- Прототип: регистрация модулей после монтирования первой строки списка (ворота `releaseModules` из `views/list/Row.vue` + таймаут 2 с). Таймлайн: транзакции модулей ушли из окна до первой строки (28 вместо ~40 транзакций до firstRow).

## A/B (одна машина, один API/IndexedDB, две сборки на портах 5401/5402, по 5 перезагрузок, 6 пар с модулями + 5 пар без)
Нагрузка машины: load average 6…20 из 24 ядер (чужие процессы), поэтому абсолютные числа выше прошлого замера 408,9.

## Где остальное время (CPU-профиль warm, busy ≈ 580 мс из 2 с окна)
- чанок точки входа (`useAuth-*.js`: zod + shared + dexie + sync) ≈ 150 мс self до DCL (85 мс): `init @zod` ≈ 84 мс — построение схем zod `@planar/shared` и shared-манифестов модулей при загрузке (packages/ — core, вне скоупа; перенос на «после первого кадра» требует асинхронной схемы Dexie);
- Dexie `onsuccess` ≈ 66 мс, `(program)` 158 мс (десериализация IDB), проекция задач 32 мс, Vue ≈ 80 мс.
- Следующий кандидат (контракт/core): лениво строить zod-схемы shared и схемы Dexie до первой строки; чтение taskAssignees/taskLabels (10 000 + 3 334 строк) не нужно для первых видимых строк.

# Попытка 2 (скоуп расширен: packages/shared, docs/contracts)

Реализовано как прототип (`attempt2-prototype.patch`, откатан):
1. `packages/shared`: все zod-схемы контракта и `args` мутаторов построены лениво (`lazy()` — Proxy, строит схему при первом обращении; `entitySchemas`, `contractSchemas`, sync/http/api схемы). Публичный интерфейс и типы не менялись, тесты shared (194) проходят.
2. `apps/web/src/tasks/projection.ts`: первая публикация проекции без связей (исполнители/метки) — общий индекс связей читается после первого кадра (rAF×2, таймаут 300 мс) и затем обновляет проекцию. Три юнит-теста пришлось дополнить ожиданием связей (`projectionSettled`).
3. Не сделано: shared-манифесты модулей (`modules/*/shared`, ≈45 % стоимости zod при старте) — они вне скоупа, а их eager-загрузка нужна синхронно тестам `moduleMutators`/`moduleIndexes` (`modules/docs/web/ui.test.ts`, `sync/__tests__/cl1a.test.ts`). Отложить их можно только через кэш индексов Dexie в localStorage + перезагрузку при расхождении — это контракт/модули, не делал.

## Почему не помогло (CPU-профиль warm, окно 140…440 мс до первой строки)
Окно целиком занято главным потоком: 245 мс из ~300 — `(program)` 113 (нативная десериализация результатов IndexedDB, разметка/стили), Vue runtime ≈ 40, Dexie ≈ 30, GC 22; код приложения и модулей — ≈ 40 мс суммарно, zod — 5 мс. Ленивый zod и отложенные связи не затрагивают то, что реально ограничивает первую строку: чтение `tasks` проекта (3334 строк, ≈ 80 мс на десериализацию) и монтирование оболочки/списка.
Профиль с 1 мс сэмплированием завышал zod (84 мс «self»); без профайлера выигрыш всего ≈ 7 мс.

## Вывод
Достигнуть ≤ 400 с запасом правкой zod/связей нельзя: эффект ≤ 7 мс при шуме ±30 мс. Остальные рычаги — другого класса (не контракт старта): читать с диска не весь проект, а окно (составной индекс `[projectId+rank]` и постраничная проекция), либо отложить монтирование оболочки (reka Select/Menu, секции sidebar) после первой строки списка. Оба меняют схему Dexie/структуру экранов — решение главной.
