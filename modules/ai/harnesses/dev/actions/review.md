---
name: Ревью MR
description: Разбирает MR задачи и оставляет комментарии к строкам diff в GitLab
runtime: agent
checks:
  - каждое замечание привязано к строке diff и объясняет, что не так
---

Сделай ревью MR этой задачи. Репозиторий проекта склонирован в текущий каталог, glab настроен. Если репозитория нет — verdict fail: «в проекте нет подключения GitLab».

1. Найди MR задачи: ключ задачи — в имени ветки или заголовке (`glab mr list --search "<ключ задачи>"`). MR не найден — verdict question: «Какой MR проверить?».
2. Получи diff (`glab mr diff <iid>`) и прочитай затронутые файлы целиком, а не только изменённые строки. Сверь изменение с описанием задачи.
3. Ищи настоящие проблемы: ошибки логики, потерю данных, дыры безопасности, гонки, отсутствие обработки ошибок, непокрытый тестами рискованный код, расхождение с задачей. Стиль и вкусовщину не комментируй.
4. Каждое замечание — отдельная дискуссия на строке diff: `glab api -X POST projects/:id/merge_requests/<iid>/discussions` с `body` и `position` (`position_type=text`, `base_sha`, `start_sha`, `head_sha` из `diff_refs` MR, `new_path`, `new_line`). В тексте — что не так, к чему приведёт и как исправить. Не удаётся привязать к строке — общий комментарий `glab mr note <iid> -m "…"`.
5. Код не меняй, ничего не пушь и MR не сливай.

Результат — verdict done:

- comment: ссылка на MR, итог одной фразой («замечаний нет» или «N замечаний») и список замечаний по одной строке;
- moveTo: «В работе», если есть замечания, которые надо исправить; иначе null.

Остальные поля результата — null.

Метка «Ждёт ответа» (важнее «остальные поля — null»): задаёшь вопрос (verdict question) — labels: [«Ждёт ответа»]; вопросов нет (verdict done) — добавь в labels «-Ждёт ответа», чтобы снять метку.
