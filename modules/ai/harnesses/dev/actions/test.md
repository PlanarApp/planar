runtime: agent
checks:
  - проверены все критерии готовности из описания задачи
  - упавшие проверки повторены, у каждой ошибки есть шаги воспроизведения

Параметры (задайте под свой проект):

- Контур: https://test.example.com — адрес стенда, где проверяем.
- Учётная запись для входа: не задана.

Проверь задачу на контуре в браузере.

1. Адрес контура выше не задан (остался example.com) — verdict question: «Задайте адрес контура в инструкции „Тестирование“».
2. Убедись, что изменения задачи уже на контуре. Обычно тебя запускает конец деплоя (конвейер ветки по умолчанию после слияния MR прошёл или его не было). Репозиторий склонирован в текущий каталог: найди MR задачи (`glab mr list --search "<ключ задачи>" --all`). MR ещё не слит или конвейер ветки по умолчанию с ним ещё идёт — жди, проверяя раз в 2 минуты, до 10 минут. Не дождался — verdict question: «MR не выкатился на контур за 10 минут — проверить позже?».
3. Составь список проверок из критериев готовности и плана в описании задачи. Критериев нет — проверь то, что описано в задаче.
4. Напиши сценарий Playwright и прогони его на контуре: скрипт в `/tmp`, запуск `NODE_PATH="$(npm root -g)" node /tmp/check.js` — глобальный `playwright` совпадает по версии с установленным chromium, свой не ставь. Скриншоты не прикладывай. В репозиторий ничего не коммить.
5. Проверка упала — прогони её ещё 1–2 раза (бывают нестабильный стенд, кеш, недоехавшая выкладка). Прошла на повторе — проверка пройдена, в comment отметь, что она нестабильна. Падает каждый раз — это ошибка.

Результат:

- всё работает — verdict done, comment: что проверено (по пункту на проверку), moveTo: «Готово»;
- есть ошибки — verdict done, comment — отчёт: что проверено и что сломано, по каждой ошибке «Шаги», «Ожидалось», «Получилось», «Контур»; moveTo: «В работе».

Остальные поля результата — null.
