runtime: agent
checks:
  - проверены все критерии готовности из описания задачи
  - у каждой задачи-исправления есть шаги воспроизведения

Параметры (задайте под свой проект):

- Контур: https://test.example.com — адрес стенда, где проверяем.
- Учётная запись для входа: не задана.

Проверь задачу на контуре в браузере.

1. Адрес контура выше не задан (остался example.com) — verdict question: «Задайте адрес контура в инструкции „Тестирование“».
2. Убедись, что изменения задачи уже на контуре. Репозиторий склонирован в текущий каталог: найди MR задачи (`glab mr list --search "<ключ задачи>" --all`). MR ещё не слит или после слияния не прошёл конвейер ветки по умолчанию — жди, проверяя раз в 2 минуты, до 30 минут. Не дождался — verdict question: «MR не выкатился на контур за 30 минут — проверить позже?».
3. Составь список проверок из критериев готовности и плана в описании задачи. Критериев нет — проверь то, что описано в задаче.
4. Напиши сценарий Playwright и прогони его на контуре: скрипт в `/tmp`, запуск `NODE_PATH="$(npm root -g)" node /tmp/check.js` — глобальный `playwright` совпадает по версии с установленным chromium, свой не ставь. Скриншоты не прикладывай. В репозиторий ничего не коммить.

Результат:

- всё работает — verdict done, comment: что проверено (по пункту на проверку), moveTo: «Готово»;
- есть ошибки — verdict done, comment: что проверено и что сломано; newTasks: по задаче на ошибку, status «Бэклог», title — суть ошибки одной строкой, description — «Шаги», «Ожидалось», «Получилось», «Контур»; moveTo: null (задача остаётся в «Test prod» до исправлений).

Остальные поля результата — null.

Метка «Ждёт ответа» (важнее «остальные поля — null»): задаёшь вопрос (verdict question) — labels: [«Ждёт ответа»]; вопросов нет (verdict done) — добавь в labels «-Ждёт ответа», чтобы снять метку.
