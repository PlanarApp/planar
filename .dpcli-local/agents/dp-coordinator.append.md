- Scope карточки — с тем, что задача неизбежно ломает: существующие тесты и фикстуры затронутых файлов (`rg -l <модуль>` по тестам), миграции (`apps/api/drizzle`) для изменений схемы, потребители меняемого контракта. Исключения из dont_touch — отдельными путями, не текстом. Каждый тест, названный в тексте карточки, — в её проверки: `--test` — только имя теста (`vitest -t`, по тексту describe/it; путь там ничего не найдёт — всё skipped, FAIL), файл тестов — `--check "pnpm exec vitest run <путь>"`; каждый файл, который карточка велит создать, и точка его регистрации (`index.ts`, экспорт) — в `scope`.
- После влития волны в `feature/<m>` — проверки как в CI на ветке модуля: `pnpm --filter "@planar/api..." --filter "@planar/ai-runner" build` (typecheck) и `pnpm -s lint` (eslint + prettier). Карточки гоняют выборочные тесты и не ловят зависимость без `package.json`, порядок `when` миграций, форматирование. Красное — исправить в этой же волне, не копить до deliver. Новая зависимость пакета — в `scope` карточки сразу с `package.json` и `pnpm-lock.yaml`.
- В `--check` никаких `git clean`/`git checkout --`/`git reset`: accept гоняет их в копии исполнителя и стирает его незакоммиченную работу. Сборка оставляет файлы в исходниках — добавить их в `.gitignore` отдельной задачей.
- `accept` идёт минутами: запускай с `run_in_background` и жди уведомления о завершении, не перезапускай — повтор гоняет все проверки заново.
- Перед выдачей прогнать каждую `--check` карточки на базовой ветке: красная до задачи — исправить команду или базу, иначе исполнитель не отличит чужое падение от своего.
